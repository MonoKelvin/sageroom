# Sageroom 技术调研与选型评估

> 版本：0.3｜调研日期：2026-11-18｜状态：推荐方案待确认，尚未进行代码 PoC\
> 输入：[初始需求](初始需求.md)；产品规格：[02](02-用户需求与产品规格.md)。本文区分官方资料事实、架构推断和待实测结论。

## 1. 调研方法与证据等级

- 优先官方文档、维护方 API/包资料、SQLite 和平台原生资料。
- 使用 Context7 核对 Tauri、模型框架和 SQLite 相关资料，再对关键变动阅读官方页面。
- 公开竞品仅比较机制，不复制实现，也不将宣传词当作符合本需求的证据。
- 页面指向 `latest`/`dev` 的内容是调研时样本，不是已经锁定的可构建版本。
- 网络失败或没有核实许可的资料直接记录为缺口，不补造“最佳方案”。

| 等级 | 含义 | 本阶段情况 |
|---|---|---|
| E1 | 官方协议/平台约束明确说明 | 已获得，来源见第 14 节 |
| E2 | 包类型、源码或维护方文档支持 | 部分已获得，仍需发布版本核对 |
| E3 | 有合理架构推断或经验预期 | 有，例如 Rust actor 比多 Node 进程更轻量 |
| E4 | 本项目环境可复现实测 | 本阶段没有；必须在用户批准编码后完成 |

不能把 E1/E2 的“存在 API”直接写成 E4 的“在 Windows 10 上效果已经验证”。本项目当前没有应用代码、安装包和实测成本数据。

## 2. 核心结论

建议路线：

```text
React + TypeScript + Vite
shadcn/ui + Tailwind CSS + Tabler Icons
                  │ 受限 IPC / 增量事件
Tauri 2 Rust 主进程
├─ 独立智能体异步 actor + 本地调度器
├─ Rig 接入层（通过能力 PoC 后采用）+ 局部 provider adapter
├─ 受控工具任务、预算和权限
├─ rusqlite 专用 DB 线程 / SQLite WAL
├─ 不可变附件文件 + 可重建缓存
└─ 操作系统凭据存储，前端无密钥读取接口
```

最重要的取舍：

1. 不给每个智能体复制一个 OS 进程；“独立”先指行为、状态与配置，是否要求进程级隔离由用户决定。
2. 不复用按 talkativeness 随机点名的群聊算法；成员自己调用模型决定发言和沉默。
3. 不让 WebView 承担后台调度；隐藏后的浏览器节流不应影响成员运行。
4. 不把整个历史每次发给模型；持久存储全历史、按预算构造上下文和检索记忆。
5. 不按天拆 SQLite 库；日期用于索引、筛选与导出。
6. 不把“OpenAI-compatible”当作统一视觉、工具、JSON Schema、thinking 和图片生成协议。
7. 不宣称无内存、不承诺模型严格拟人、不把平台通知当作保证送达。
8. 不默认执行代码，不赋予智能体群主任意应用管理权。

## 3. 同类机制比较

### 3.1 常见即时通讯桌面客户端

可借鉴：未读游标、引用、附件生命周期、消息撤回、关闭隐藏和托盘常驻。不能直接照搬：服务器时间、多人网络权限、服务端推送与云历史，因为 Sageroom 首版建议是单机本地群聊。

### 3.2 SillyTavern Group Chats

官方文档提供 Manual、Natural Order、List Order、Pooled Order 和 Auto-mode。其 Natural Order 包括名字提及、talkativeness 概率和没有人激活时随机选人；Auto-mode 在回合后延时再次生成。

可借鉴：成员独立角色定义、共享群历史、引用式角色语境、启停与成员管理。

不能直接采用：

- 概率点名和随机兜底不符合“是否接话由各成员模型判断”。
- 固定 auto-mode 连续生成不符合“应该自然安静、不是无限消息”。
- 合并所有人物卡成同一提示词可能混淆身份，不能代替每个成员独立 SKILL。
- 强制发言接口不应作为日常提及的默认语义。

因此优先复用 UI/SDK 等基础依赖，而不是直接套用不符合核心行为的多角色聊天引擎。

## 4. 桌面与运行时

### 4.1 Tauri 与备选

| 方案 | 与需求匹配 | 主要代价 | 判断 |
|---|---|---|---|
| Tauri 2 + Rust | 满足指定路线，使用系统 WebView，原生能力与本地服务清楚分层 | Rust 学习/平台 WebView 差异，原生效果需实测 | 推荐 |
| Electron + Node | JS 生态成熟、浏览器行为较统一 | 打包完整 Chromium，资源目标更难；偏离明确技术要求 | 不作为首选 |
| 纯 Web/PWA | 开发部署简单 | 无法可靠满足桌面托盘、退出后/后台行为、任意本地迁移 | 不满足首版 |
| 每成员独立进程 | 进程故障隔离更强 | IPC、打包、启动、日志、取消及资源管理成本高 | 仅用户确需隔离时重新评估 |

Tauri 的轻量优势不能免除整个进程树的测量。WebView2 子进程、图片解码和 GPU 工作都需纳入资源统计。

### 4.2 Windows 能力核实

| 能力 | 资料事实 | 设计结论 |
|---|---|---|
| WebView2 | Windows 应用依赖 Runtime；Windows 11 通常内置，部分 Windows 10 设备没有 | 安装前检测，并设计联网/离线安装策略 |
| 无边框阴影 | Tauri API 提供相关属性；Windows 无边框阴影可能带 1px 白边，Windows 11 有圆角 | 原生阴影是首选但不能承诺完全无边；须用户接受实测外观 |
| 毛玻璃 | Mica 为 Windows 11；Acrylic 在部分版本拖动/缩放有性能问题 | 不默认强制 Acrylic；实色/CSS 材质为性能降级方案 |
| 桌面背景模糊 | CSS backdrop-filter 模糊的是 Web 内容背后的合成区域，不天然等同 OS 桌面模糊 | 文档和 UI 分清 CSS 与原生材质 |
| 隐藏继续运行 | 应用可拦截关闭隐藏，Rust 持有托盘/任务 | 显式退出停止任务；睡眠和进程终止不保证继续 |
| 托盘闪烁 | 有 setIcon 等能力，没有本次核实的一键 blink 合同 | Rust 定时交替合成图标；可关闭、限时、勿扰优先 |
| Windows 数量角标 | `setBadgeCount` 不支持 Windows；有任务栏 overlay 能力 | 托盘数量单独绘制，任务栏 overlay 是不同实现 |
| 系统通知 | 安装后应用需要实测；开发模式标识可能不同 | 不能以 dev 模式通知截图作为发布验收 |
| 勿扰 | OS 能抑制原生通知，但未必抑制应用自己播放声音/托盘闪烁 | 提供应用内勿扰，不能绕过 OS 偏好 |

macOS/Linux 不应承诺同样的阴影、角标、点击和 tooltip 行为。首版建议 Windows 11 优先，测试范围以 Q-01 批准矩阵为准；Windows 10 19045 仅在明确纳入后安排设备与额外验证，不默认要求双平台验收。

### 4.3 后续手机端

可以复用：领域实体、部分 Rust 存储/网络/上下文逻辑、React 的部分业务状态和 API 合同。

不能简单复用：常驻托盘、桌面窗口、任意文件路径、密钥库具体实现、系统通知注册、后台长驻调度。Android/iOS 对后台执行有明确限制，未来需重新决定前台运行、受限后台任务、推送或可选服务端，而不是承诺手机也能无限实时监控。

## 5. 前端依赖

| 领域 | 推荐 | 备选或边界 |
|---|---|---|
| UI 运行 | React + TypeScript | 与 shadcn 和现成依赖生态契合；不为预研同时研究多个框架 |
| 构建 | Vite | 正式版必须对 WebView 基线设置 target，不只测试本机 Chrome |
| 组件 | shadcn/ui | 分发源码，项目承担更新维护；按批准时的 React 变体和安装体系锁定 |
| 布局 | Tailwind CSS v4 候选 | 官方基线 Chrome 111 / Safari 16.4 / Firefox 128；未来旧 WebView 不满足时需调整 |
| 图标 | `@tabler/icons-react` | 按需导入/tree shaking；不同时引入另一整套图标 |
| 聊天虚拟列表 | `react-virtuoso` 免费核心 | 核实样本 4.18.23 为 MIT；样本版本不是冻结版本 |
| 专用 Message List | `@virtuoso.dev/message-list` | 商业许可证；未经确认预算不能误纳入免费方案 |
| emoji | `emoji-picker-react` 候选 | 本轮 npm 元数据样本为 5.1.4、MIT、Node ≥18；组件能力见当前 README，实际 React/WebView 与素材许可仍须冻结验证 |
| 颜文字/表情收藏 | 少量明确许可数据 + 本地附件管理 | emoji 选择器不是完整 GIF 表情管理器 |
| 表单/校验 | 复用成熟表单库，Zod 做前端验证候选 | 后端仍需独立验证，不能相信前端 schema |
| 动画 | CSS 优先 | 必要复杂交互才引入 Motion，不堆多个动画库 |
| Markdown/代码 | 安全 Markdown 子集 + 按需高亮 | 原始 HTML 关闭，不执行代码，不加载远端嵌入 |

Vite guide 本次说明 Node 最低为 20.19+ / 22.12+。实际开发选择仍受支持的 LTS 并满足所有依赖 engine，不把“最低支持”误作“推荐安装老版本”。

对聊天列表必须验证：前插历史、动态图片高度、读旧消息时新消息、引用跳转、撤回替换、深色、缩放和输入区变化。不能只演示一屏静态文本。

## 6. 多模型接入

### 6.1 框架路线

| 路线 | 优势 | 风险 | 结论 |
|---|---|---|---|
| Rig + Rust actor | 复用 provider、消息和工具抽象，不引入 Node | provider 能力和 SDK 支持时间不完全一致；Native/Tool/Prompted 输出保证不同 | 条件首选，PoC 通过后锁定 |
| Rust `reqwest` adapter | 协议、鉴权、SSE、扩展字段可精确控制 | 全量自研增加维护、测试和升级成本 | 只补必要协议差异，或 Rig 不适配时承担窄接入层 |
| TS AI SDK sidecar | provider/图片生态丰富，TS 开发便利 | 额外运行时、IPC、打包、升级和生命周期 | 只有 Rust 路线确实阻塞关键能力时才引入单一 sidecar |
| 完整多智能体编排服务 | 大量内建 orchestration 功能 | 容易把宿主控制、预算和独立决策交给不可控循环 | 本需求不默认需要 |

宿主不能把“SDK agent.run() 直到完成”当作安全边界。每一轮外部请求、工具执行和群消息都需要应用层预算、版本及权限校验。

### 6.2 兼容性事实

- JSON object 格式不等于完全遵守业务 JSON Schema；结构正确也不代表目标消息、参数或授权正确。
- 既有 Rig 样本源码以 Native、Tool、Prompted 区分结构化输出，后两者是尽力约束；本轮 v0.46.0 资料显示 runner/tool 接口存在迁移，不能假定旧样例类名在锁定版本仍可用。领域设计保留保证等级，实际 SDK API 必须按选定发布版本验证。
- Anthropic 原生 Messages 与 OpenAI 兼容层存在功能差异；不能通过兼容层声明所有原生能力。
- 模型名不能作为唯一能力判断；同一个品牌的不同模型、端点和 API 版本可能不同。
- 视觉输入、工具+schema 同时使用、reasoning、usage 和缓存分别测试。
- 未知能力在注册表中记录为 unknown，不默认 true，也不能随机自动选择不同 provider。

### 6.3 Thinking 的新资料核验

本次直接读取的 DeepSeek Thinking Mode 页面说明：

- 当前说明中的 thinking 默认开启，OpenAI Chat Completions 格式以 `thinking.type = disabled` 关闭；Responses 格式以 reasoning effort `none` 表达关闭。
- 部分采样参数在 thinking 模式不生效，可能被静默忽略。
- 带 tools 的 thinking 回合要求正确回传 `reasoning_content`，缺失可能 400。

这是调研日期对应官方页面的协议说明，不推广为“所有历史 DeepSeek 模型一直如此”，也不保证未来不变。正式实现需按用户实际选用模型和端点做合同测试。

Provider 原生协议可能需要保留不可见的工具会话状态。该状态与群消息分开，只用于必要回合，不向用户展示私有思维链、不进入普通日志/长程记忆；详见 [07](07-模型接入与工具执行设计.md)。

## 7. 工具接入与媒体

### 7.1 图片生成

- 单独的 ImageAdapter，不沿用聊天 completion 的通用猜测。
- 支持协议型态：同步返回 URL/base64/bytes，或异步 job ID/poll。
- 尺寸、参考图片、mask、数量、取消和计费单位按提供方能力区分。
- SDK 可能把多图拆成多个请求并重试，预算必须在实际请求边界计入。
- 未确认幂等性的付费请求不自动重试；响应丢失时优先查询 job 或显示结果未知。
- 远端图片下载经 URL、重定向、类型、字节和解码限制，生成结果落地本地附件后才发布。

### 7.2 搜索与热点

Tavily 等独立搜索服务是候选，搜索和网页正文提取是不同能力。新闻发布时间可能缺失或是估计，不能将“检索到”当作“事实已证实”。

默认只在明确授权下联网；网页正文被当作资料，不授予模型新的工具权限。不要求为聊天自动爬取大量新闻，更不能让每个成员高频无条件联网。

### 7.3 计算和代码

表达式计算采用受限解析器并只开放数值操作；不使用 JS eval、shell、Python 动态执行。具体维护中的库在 PoC 时核查。

简短代码首先是生成、展示和复制。若用户希望真实执行，需单独确认隔离环境、网络、文件权限、资源限制和依赖管理，不能在本文默认带入。

## 8. SQLite 与驱动

### 8.1 方案比较

| 存储 | 优势 | 代价/不匹配点 | 选择 |
|---|---|---|---|
| 单 SQLite | 本地事务、索引、查询、引用和迁移成熟 | 单写者、文件句柄及 WAL 备份需正确处理 | 推荐 |
| 日/周多 SQLite | 单文件体积小、归档直观 | 跨期引用、搜索、记忆、备份复杂 | 不默认采用 |
| JSON/NDJSON | 易读易导出 | 索引、并发、改写、删除、复杂查询需造轮子 | 用于导出/配置，不作聊天主存储 |
| 服务端数据库 | 共享和并发成熟 | 与轻量本地单机范围不符 | V1 不需要 |

### 8.2 驱动推荐

推荐 `rusqlite` 的 bundled SQLite + backup 能力，通过专用线程执行数据库工作。这样复用成熟同步 API，避免阻塞 Tokio runtime，也方便 online backup 和 SQLite 专有功能。

SQLx 是有效备选，SQLite 的异步接口仍由后台线程执行底层阻塞操作；若选择 SQLx 就不要再为了某个接口同时引入两套 SQLite driver，避免原生链接版本冲突。默认本套设计以 rusqlite 为基线，若用户/团队有 SQLx 强偏好，在批准时整体替换。

配置建议：WAL、短事务、序列化写、少量读连接、foreign_keys、busy_timeout、默认 synchronous=FULL。FULL/NORMAL 是持久性取舍，NORMAL 不能被表述为断电后绝不丢已提交记录。

WAL 允许读写并发但仍只有一个写者；长事务会妨碍 checkpoint；网络共享不作为默认数据目录。

### 8.3 中文搜索

- `unicode61` 不是中文分词器，连续中文不能保证按词命中。
- FTS5 trigram 支持三字符及以上子串，是本地首版候选。
- 一至二字符搜索走参数化扫描/`instr`，附日期/成员筛选、取消和时间预算；不能悄悄只搜索近期。
- trigram `MATCH` 不足三字符不返回结果，某些 LIKE/ESCAPE 情况无法利用索引。
- 用户搜索采用 literal 子串语义；FTS5 trigram 仅产候选，最终 `instr` 复核，与一至二字符扫描一致。trigram 默认大小写不敏感，不能把 MATCH 当作大小写/重音/全半角完全一致的最终匹配。
- MATCH 若用于长 literal 短语保留 detail=full；不把 detail=none 的长 MATCH 限制误当无结果。候选完整性不能保证时走同语义可取消扫描，详细合同见 05。
- 自然语义、同义词或更强排序需要后续分词/embedding，不用首版承诺免费全能搜索。
- 索引与撤回/删除必须在同一事务同步，历史回填须 rebuild 测试。

## 9. 附件、备份与迁移

### 9.1 附件方案

文本及引用入库，原始文件入数据目录中的不可变对象区。数据库只保存对象 ID、相对路径、类型、大小和哈希。缩略图是可重建缓存。

文件先写 staging、检查实际大小/类型/解码限制、flush 和同卷发布，再提交引用；失败后清理孤儿，不能删除用户原件。

### 9.2 备份的一致性

- WAL 模式直接复制 `chat.db` 可能漏已提交 WAL 数据；同时分别复制 DB/WAL 也不能保证时间一致。
- 使用 SQLite online backup；`VACUUM INTO` 是可选一致快照，但 CPU、中断和成功发布需要处理。
- 数据库快照不等于整个应用快照：配置、不可变附件与 GC 需要协调冻结/引用 pin。
- 正式备份必须包含版本 manifest、对象清单、大小及 SHA-256；checksum 是损坏检测，不是加密或来源认证。
- 首版恢复建议整体替换并保留当前数据回滚，不承诺不同聊天库随意无损合并。

### 9.3 Windows 目录迁移

跨卷不能把目录 rename 当原子操作，Windows 可能执行 copy/delete，ACL 和句柄也有区别。推荐预检、停止数据修改、释放相关句柄、复制到目标 staging、验证、同卷发布目标、原子切换固定 bootstrap 指针、重开验证、保留原目录。

迁移状态持久化，启动后恢复或回滚。不手工删 WAL、不先删源、不在故障时新建空库掩盖损坏。

### 9.4 导入攻击面

在新 staging 验证 ZIP，拒绝绝对/越界路径、符号链接、junction/reparse point、Windows ADS/设备名、归一后重复路径。按实际解压流量限制对象数、单项和总字节，不能相信压缩头声明。导入 SKILL 和配置也是不可信输入，不自动启用或联网。

## 10. 凭据与数据加密

Windows 建议操作系统 Credential Manager，通过 Rust SecretStore 使用，前端只写入/更新和获知是否配置。当前 keyring 文档建议需要明确平台 store 的应用选择 `keyring-core` + 特定 store，而不是照搬旧 feature 或引入无关 CLI 模块。精确 store 和 MSRV 需冻结前编译确认。

边界：

- Credential Manager 保护当前用户凭据，但不是“同一账户恶意进程永远读不到”的隔离。
- DPAPI 一般与用户/设备绑定；不能用 LOCAL_MACHINE 模式保存私人密钥，也不能认为 blob 可任意跨设备迁移。
- Stronghold 是可选跨平台加密 vault，但需要合理解锁/KDF体验及收紧 JS 权限。
- 普通 SQLite 默认不加密；密钥加密不等于所有聊天加密。
- 默认备份不含 API Key；恢复后重新输入。如果要含密钥备份，必须另做口令认证加密和明确授权。

是否需要整个聊天库/附件静态加密是用户决策，会影响搜索、迁移、密码恢复和交付范围。

## 11. 长期记忆和上下文

推荐分层：近期原文、来源可追溯的群摘要、成员独立记忆、按需检索历史。不引入独立向量服务，也不永久传送全部历史。

- 时间段和上下文预算触发压缩；模型判断话题边界、摘要和记忆含义。
- 代码决定最大 token、调用额度、失效来源和权限，不随机抽取“记忆故事”。
- 原始聊天长期保留，摘要不是原记录的替代物。
- 用来源 message IDs、范围、content epoch、模型/SKILL 版本管理撤回和更正。
- 删除/撤回后不能通过旧摘要、FTS 或向量结果回灌未来上下文。
- 单靠 embedding 不解决事实正确性、角色隔离和隐私；首版先用本地文本与结构化记忆。

详见 [06](06-上下文与长期记忆设计.md)。

## 12. 自然聊天 SKILL 调研结论

既有调研记录未完成核实某个第三方“最佳去 AI 味 SKILL”的原仓库、内容和许可；原记录提到搜索超时/验证挑战、GitHub CLI 未认证及提取失败，本轮搜索也未获得可用证据。因此不冒称已找到“最新最好用”的成品，不直接复制来源不明提示词。

建议先独立写适用于实时群聊的 SKILL，再在能访问且许可明确时补充公开素材：

- 普通成员平等，不默认服务用户；群主四项管理权限不改变聊天地位。
- 不强迫每句总结、列表、免责声明或“还有什么可以帮你”。
- 允许短句、沉默、休息、分条、引用和自然结束。
- 角色偏好与表达稳定，不将所有成员改成相同的“口语 AI”。
- 不为了拟人随机制造错字、攻击性或撤回。
- 实时新闻需真实资料，不虚构经历、不隐瞒智能体身份。

文章 humanizer、检测器规避和群聊自然度不是同一任务。验收使用固定场景、角色盲评与统计指标，不声称能骗过检测器或永远被当成人类。

### 13.2 调用成本模型

设活跃成员 N、进入模型观察的事件 E、平均每次上下文 token I、输出 O；一次决策可能已经包含发言，不强制双调用。

```text
语言模型费用 = Σ每次请求(输入未缓存量 × 输入价 + 缓存量 × 缓存价
                        + 普通输出量 × 输出价 + 提供方要求的 reasoning 计费)
工具费用     = Σ搜索 credits + Σ生成图片数量/尺寸费用 + 其他授权工具费用
总费用       = 决策 + 修复/重试 + 工具后续 + 摘要/记忆 + 工具费用
```

纯演示算例，不代表实际使用预测或当前价格：4 位活跃成员、每天 200 个合并后的观察机会、平均输入 1500 tokens、输出 120 tokens，基础约 800 次请求、120 万输入与 9.6 万输出 tokens；如果成员消息继续触发机会，次数还会增加。相反，模型休息及事件合并可减少请求。最终必须实测。

总预算未知时不能把未知单位当零；缓存/思考等计费重叠由 adapter 明确，避免重复加总。币种不同不直接相加。

### 13.3 编码批准后必须先做的验证

1. Tauri 原生壳：按 Q-01 批准 OS 矩阵验证 WebView2、阴影/白边、材质、DPI、托盘、退出和 installed notification；Windows 10 只在获准范围内测试。
2. 模型合同：一条 OpenAI-compatible、用户实际 DeepSeek、Anthropic 原生；schema、thinking、vision、tools、usage、失败与取消。
3. 1/4/8 actor 的空闲与聊天资源、费用、背压和安静能力。
4. 动态高度历史：10 万条、多图/GIF、前插、引用、撤回、看旧消息时到达新消息。
5. 中文全文检索及短词扫描，撤回/删除索引一致性。
6. 备份时附件 GC/导入/配置修改冲突以及完整恢复。
7. Windows 跨卷、中文长路径、杀毒占用、各阶段崩溃恢复。
8. Credential store、CSP、IPC、ZIP 安全与不自动执行导入内容。

PoC 失败的选择流程：先记录事实与最小替代方案，再与用户确认有范围/架构影响的改变；不以“遇到问题”为由直接换框架、执行用户代码或降低安全。
