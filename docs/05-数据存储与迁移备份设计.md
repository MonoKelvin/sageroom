# Sageroom 数据存储、迁移与备份详细设计

> 版本：0.2｜状态：待评审，SQL 为合同说明，尚未创建数据库｜日期：2026-11-18  
> 数据库方案依据见 [01](01-技术调研与选型评估.md)。上下文失效见 [06](06-上下文与长期记忆设计.md)，安全导入见 [09](09-安全隐私与可靠性设计.md)。

## 1. 存储目标与边界

- 完整聊天历史、消息顺序、引用、提及、任务、配置版本和记忆来源可追溯。
- 数据位于用户应用目录；安装目录可以只读，卸载/升级不静默清空用户数据。
- 数据根支持迁移，bootstrap 与操作系统凭据不随迁移复制。
- 原始附件不可变，缓存可重建，文本长期保留与附件保留规则分开。
- SQLite 事务保证业务状态一致；文件系统与 SQLite 之间用发布顺序和恢复日志协调，不虚构跨文件系统大事务。
- 备份必须能实际恢复；可读导出不是恢复包。
- 默认 SQLite 和附件不加密，若需要静态加密须用户确认。

## 2. 目录布局

通过 Tauri 的用户应用路径解析 API 获取目录，不硬编码用户名或 Windows 盘符。建议本地应用数据目录，不用 Roaming 或网络共享作为 WAL 数据根。

```text
固定 app_local_data_dir/
  bootstrap.json                 # 当前 data_root、根 UUID、格式版本
  bootstrap.previous.json        # 指针回滚候选
  maintenance/                   # 迁移/恢复操作日志
  instance.lock                  # 单实例/维护锁，不能随便删除

当前 data_root/
  data-manifest.json             # data_root UUID、schema/格式版本
  chat.sqlite3
  chat.sqlite3-wal                # SQLite 管理，禁止手动清除
  chat.sqlite3-shm
  agents/<agent_id>/
    current.json                 # 可查看/编辑的配置投影，不含密钥
    SKILL.md                     # 当前 SKILL 的投影
    revisions/<revision>/        # 不可变版本文件
      agent.json
      SKILL.md
  profiles/                      # 全局预设的版本化投影
  attachments/objects/aa/bb/<hash>
  cache/thumbnails/
  staging/                       # 未发布上传及受限暂存
  exports/                       # 用户选择保留的可读导出
  backups/                       # 可选默认备份位置，建议选其他盘/目录
  logs/                          # 脱敏且轮转的运行诊断
```

文件内容之外的基础状态以数据库有效快照为准，投影同步规则见第 8 节。目录名来自受控 ID/hash，不拼接昵称和原始文件名。

数据根的 UUID 防止用户把任意同名 `chat.sqlite3` 指给应用。恢复包形成新的受控根，不能直接信任包内 bootstrap 路径。

## 3. SQLite 策略

### 3.1 驱动与连接

推荐 `rusqlite` bundled SQLite、backup feature、专用数据库 worker。网络 runtime 不直接执行同步 SQLite。

每个连接明确启用：

- `foreign_keys=ON`。
- WAL（只在初始化/维护阶段配置，非每条写入重复设置）。
- 默认 `synchronous=FULL`，保护聊天提交的断电持久性；实际文件系统和硬件仍有边界。
- 有限 `busy_timeout`，超时返回 typed error，不无限等待。
- 不启用用户指定扩展加载。
- 读取事务短且可取消；导出/搜索不能无限阻塞 checkpoint。

一个写 worker，少量读连接；读 worker 的规模和 checkpoint 策略实测后冻结。所有写事务先完成提交再向 actor/UI 广播。

### 3.2 索引与分页

- `message_seq` 是整数主序号，不靠 created_at 排序。
- 聊天分页使用 before/after/around 序号，不用对大历史的 OFFSET。
- 日期、发送者、任务状态及来源范围单独索引。
- FTS 只索引可见未撤回文本，删除/撤回事务同步更新。
- 原始消息正文不反复复制到事件日志、引用快照和诊断日志。

## 4. 概念实体关系

```text
room ── owner_participant
 │
 ├─ participants ── agents ── agent_config_versions
 │      │
 │      └─ messages ── message_parts ── attachment_refs ── attachments
 │             ├─ mentions
 │             ├─ quote_message_id → messages
 │             └─ recall/delete state → content_epoch
 │
 ├─ announcements → messages
 ├─ runtime_plans / actor_cursors
 ├─ decisions / actions / jobs
 ├─ context_segments / summary_versions
 ├─ memories / memory_sources
 ├─ provider_profiles / credential_refs / tool_profiles
 ├─ model_requests / budget_reservations / usage_ledger
 ├─ domain_events
 └─ data_operations / backup_manifests
```

所有表有需要的外键和唯一约束；状态枚举在领域合同与 schema check 中保持一致。禁止任意可执行代码或 provider raw response 入普通业务表。

## 5. 数据字典

### 5.1 房间与参与者

| 表 | 关键字段 | 约束/说明 |
|---|---|---|
| `room` | id、name、owner_participant_id、params_json、version、content_epoch、created_at | 首版固定一个 room；群参数只保存批准白名单；owner 指向有效参与者 |
| `participants` | id、kind(user/agent)、display_name、avatar_attachment_id、profile_json、profile_revision、status、created_at、deleted_at | 一个真人身份；公开简介/称呼/可选性别，改名/头像不改 ID；删除为 tombstone |
| `participant_changes` | id、participant_id、actor_id、old_revision、new_revision、changed_fields、created_at | 真人编辑/智能体合法自主资料修改可追踪，禁止密钥/权限数据 |
| `agents` | participant_id、agent_type、enabled、active_config_revision | 一个 participant 对应一个 agent；有效配置引用不可变版本 |
| `announcements` | id、message_id、title、author_participant_id、room_version_at_publish | 正文用 message parts；不把通告当 system prompt |
| `group_changes` | id、actor_id、old_version、new_version、changed_fields、created_at | 记录四项权限操作；不存密钥/模型配置 |

群主不能因 owner 字段取得普通消息特殊优先级；群主变化不重写历史通告作者。删除当前群主前须由本地用户选择新群主或转回自己，不留下悬空 owner。

### 5.2 消息与内容

| 表 | 关键字段 | 约束/说明 |
|---|---|---|
| `messages` | seq、id、room_id、sender_id、sender_snapshot_json、kind、created_at、quote_message_id、origin_action_id、chain_id、state、recalled_at、deleted_at、recall_deadline_at、metadata_json | kind 为 chat/announcement/status_notice；chat/announcement sender 必填，应用小标记 sender 可空且带 subject ID；seq 单调、id/origin action unique、quote 同 room |
| `message_parts` | message_id、ordinal、kind、text、attachment_id、metadata_json | ordinal 有序；text/attachment/emote 明确，emote 解析有效表情和附件；不接受任意 HTML |
| `mentions` | message_id、target_participant_id、mention_kind、ordinal | @all 在发送时展开/记录接收者快照，不能按之后成员列表追增 |
| `attachment_refs` | attachment_id、ref_kind、ref_owner_id、created_at | 聊天、头像、表情收藏、任务、有效备份等不同引用 |
| `read_state` | viewer_id、room_id、last_read_seq、updated_at | 首版本地用户一个阅读游标，单调推进 |
| `message_search` | message_id/seq、可见文本索引 | 具体 FTS5 schema 第 7 节，撤回删除不能残留正文 |

`sender_snapshot_json` 只包含当时昵称/头像引用/成员类型等显示字段，不含完整 SKILL 和凭据。成员改名不会把过去聊天全部改成新昵称，当前成员详情另取最新信息。

`metadata_json` 只保存 04/06 白名单中的 topic_tags、emotion_label 等公开/附加描述和宿主来源元数据；没有任意执行指令或 provider raw body。撤回/删除同时清理可能含原文的 annotations。status_notice 的 subject_participant_id、offline_episode_id 和昵称快照用于点击诊断，应用标记不成为模型社交触发。

消息状态：visible / recalled / deleted。recalled/deleted 占位可保留 sender/time/ID，正文和引用可读投影移除。是否在加密审计中另保留撤回原文不是默认需求，本设计不保留可重新召回的原文副本。

### 5.3 配置与凭据引用

| 表 | 关键字段 | 约束/说明 |
|---|---|---|
| `provider_profiles` | id、name、protocol、endpoint、active_revision、status | endpoint 修改需重新验证/授权绑定 |
| `profile_versions` | profile_id、revision、non_secret_json、created_at、source | 不可变全局模板，不含明文 key |
| `credential_refs` | id、platform_store_key、bound_endpoint_fingerprint、status | 只记录系统库索引和绑定，不保存密钥 |
| `agent_config_versions` | agent_id、revision、config_json、skill_text、config_hash、skill_hash、source_profile_revision、created_at | 不可变；已激活版本是权威运行快照 |
| `tool_profiles` | id、type、version、non_secret_json、credential_ref | 搜索/图片协议独立于聊天 provider |
| `authorizations` | id、scope、actor_id、tool_id、endpoint_fingerprint、mode、limits、created_at、expires_at | 本地用户授权；模型不能自行插入 |
| `app_settings` | id/key、value_json、revision | 生命周期/通知/安全预算与群参数分离 |

全局参数复制，secret_ref 引用共享；换 key 会影响使用该凭据的服务，修改普通模板不会改既有成员副本。

### 5.4 运行、调用与工具

| 表 | 关键字段 | 约束/说明 |
|---|---|---|
| `actor_cursors` | agent_id、last_observed_seq、pending_through_seq、config_revision、updated_at | 区分本地收到与模型已经观察 |
| `offline_episodes` | id、agent_id、config_revision、reason_code、notice_message_id、started_at、resolved_at | 同故障周期唯一 notice；Offline/重试上线持久化，重复错误/重启不重复刷标记 |
| `runtime_plans` | id、agent_id、type、due_at、expires_at、config_revision、state | 保存合法唤醒，不默认持久化未发送正文 |
| `decisions` | id、agent_id、request_id、observed_through_seq、content_epoch、config_revision、participation、status、created_at | 默认只保存决策类型与执行元数据，不保存私有思维链 |
| `actions` | id、decision_id、ordinal、kind、state、target_id、created_at | `(decision_id, ordinal)` unique；避免重复发言/撤回 |
| `tool_jobs` | id、actor_id、origin_message_id、tool_profile_revision、params_json、approval_hash、state、depth、remote_job_id、cancel_state、result_ref、created_at、updated_at | 受控参数，非幂等未知结果不能自动重发 |
| `model_requests` | id、agent_id/job_id、purpose、provider_revision、started_at、finished_at、status、finish_reason、provider_request_id、usage_json、cost_status | 所有请求含 observe、修复、失败/取消，未知收费明确 |
| `budget_reservations` | id、request_id/job_id、unit、currency、reserved_amount、state、expires_at | 发请求前原子预留；未知结果不直接释放为零 |
| `usage_ledger` | id、request_id、usage_components、price_revision、currency、estimated_cost、confidence、settled_at | usage 与账单不同，币种不混加 |

私有 provider 协议会话状态默认只在活动工具回合内存中保存；若断电恢复确需保存，必须使用 SecretStore/Vault 加密并限期，不存普通 `params_json` 或聊天表。

### 5.5 上下文、摘要和记忆

| 表 | 关键字段 | 约束/说明 |
|---|---|---|
| `context_segments` | id、room_id、start_seq、end_seq、topic_label、content_epoch、state | 压缩单元，不是永久丢弃消息的分片 |
| `summary_versions` | id、segment_id、version、summary_text、source_epoch、source_hash、model_revision、state、created_at | 状态 valid/stale/rebuilding/failed |
| `summary_sources` | summary_id、message_id | 可撤回/删除的来源追踪；便于精确失效 |
| `memories` | id、scope(room/agent)、owner_agent_id、kind、content、confidence_class、valid_from/to、version、state、user_pinned | 区分事实/自述/观点/待办；不把置信当真伪保证 |
| `memory_sources` | memory_id、message_id、summary_id 可选 | 至少能追溯原始消息；不可只指向二次摘要而失去原来源 |
| `memory_exclusions` | id、owner_agent_id、source_message_id/segment_id、reason、created_at、revoked_at | 用户选择不再从这些来源生成该成员记忆；可撤销，不能借此跨 owner 读取 |
| `memory_embeddings` | memory_id、embedding_profile_revision、vector、source_hash、state | 可选，默认不需要；来源变化先失效 |

删除来源后相关摘要/记忆立即在查询端排除，即使后台重建尚未完成也不能召回旧正文。

### 5.6 附件、事件和维护

| 表 | 关键字段 | 约束/说明 |
|---|---|---|
| `attachments` | id、sha256、relative_path、original_name、media_type、byte_size、width/height、frame_count、state、created_at、expires_at | 路径受控；original_name 只用于显示；hash/size 不改变 |
| `emote_collections/items` | collection/item ID、display_name、attachment_id、source/license、sort_order | 表情收藏是独立引用，不能随原消息过期误删 |
| `domain_events` | seq、id、kind、entity_id、entity_revision、payload_json、created_at | 与业务事务同写；payload 不重复保留消息原文 |
| `event_consumer_cursors` | consumer_id、last_event_seq | actor/UI 不漏事件，可重查 |
| `data_operations` | id、kind、phase、source_root_uuid、target_handle、manifest_hash、state、created_at | 固定 bootstrap 另有恢复日志，DB 卸载时仍可恢复 |
| `backup_manifests` | id、path_hint、format_version、manifest_hash、created_at、verification_state | 默认不作为永久密钥载体 |
| `attachment_pins` | operation_id、attachment_id、reason、expires_at | 备份/导出/任务暂时保护，恢复后及时释放 |

持久事件按消费者水位和诊断保留策略清理；不无限增长为第二套聊天库。事件不足以重放整个数据库时，消费者重取快照。

## 6. 关键事务

### 6.1 消息提交

1. 校验本地请求幂等键或动作 ID、sender、quote、mentions 和附件准备状态。
2. 检查 @all/通告当前群主权限；普通文本“@所有人”不产生该权限。
3. 插入 messages，获取 seq；插入 parts/mentions/refs。
4. 更新 FTS 和必要任务关联。
5. 写 domain_events（只含 ID/seq/必要元数据）。
6. COMMIT 后更新内存状态、通知和 actor 观察范围。

COMMIT 失败时不广播“已发送”，前端草稿保留。进程在 COMMIT 后、广播前崩溃，启动通过事件/状态重查恢复；unique 约束防止重复发送。

### 6.2 撤回/删除

撤回不足 120 秒，自己消息，当前状态 visible；同一写事务：

- 标记 tombstone，移除可读正文/搜索内容和引用投影。
- 增加 room.content_epoch。
- 通过 source 表标记受影响摘要/记忆/vector stale。
- 保留必要 ID、作者、时间和状态，不保留旧正文在事件里。
- 写 Recalled 事件，COMMIT 后取消受影响候选/通知预览。

附件引用是否释放与模型已传输边界分开；新的聊天占位不等于远端内容已删除。明确删除范围时把无引用附件交 GC，不能在该事务直接删正在备份的文件。

### 6.3 群管理

读取 room_version 与 owner，校验 actor 是当前群主和 patch 字段。乐观更新必须匹配 expected_version。通告通过消息事务写入，对话层不因此增加权力。Owner 修改只由本地应用管理用例执行。

### 6.4 预算

预算预留、请求创建和配额递增必须串行事务完成，避免多个 actor 同时超额通过。实际 usage 结算后调整预留；取消/未知结果保持不确定标记，按政策等待查询或账单核对，不立即当免费释放。

## 7. 搜索合同

### 7.1 语义

首版“全文搜索”指 Unicode 子串匹配与过滤，不承诺中文语义理解。

- 至少三个 Unicode 字符：使用 FTS5 trigram 候选路径。
- 一到两个字符：用参数化精确子串扫描，支持时间/成员过滤和取消。
- 空格/特殊字符/emoji/全半角的规范化规则明确测试；不能只按字节长度判断三字符。
- 用户输入不直接拼成 FTS 表达式；普通搜索转义/编码为应用支持的查询子集。
- LIKE/ESCAPE 的索引适用性据实测选择，不假定所有模式都走 trigram。
- 查询失败和超时显示未完成范围，不悄悄只搜近期若干记录后报“全群无结果”。

### 7.2 同步与重建

新增、修改可读投影、撤回、删除与 FTS 在同一事务同步。数据库升级或索引策略变化可从有效正文重建。FTS 不是原始数据，损坏时可重建，但重建时查询要有状态提示。

搜索结果只返回必要片段和 ID，点击目标再加载 around_seq；不一次把全部命中正文送到 WebView。

## 8. 独立配置文件与数据库快照

### 8.1 明确唯一运行基线

- 每个成员拥有独立 `current.json` 和 `SKILL.md`，方便查看、编辑和导出。
- 运行时使用已激活、不可变的 DB `agent_config_versions` 快照。
- 文件外部修改是“候选配置”，不是未验证就生效的第二套真相。
- 全局模型/性格预设复制为成员参数副本；共享 secret_ref 的真实关系另行显示。

### 8.2 激活流程

1. 收到 UI/外部文件候选，验证 schema、SKILL 大小、能力、权限与 expected_revision。
2. 生成新 revision，在同卷 staging 写不可变版本文件并校验哈希，flush 后发布到 revisions。
3. 数据库事务插入相同内容快照并切 active revision；写 ConfigActivated 事件。
4. COMMIT 后取消旧 actor 候选、加载新快照。
5. 更新 current.json/SKILL.md 投影和已物化哈希。

崩溃处理：

- 文件已发布而 DB 未提交：不可见孤儿版本，延迟 GC。
- DB 已提交但投影未更新：启动以 DB 版本修复投影，不当作用户主动回退。
- 投影 revision 旧于 DB：视为旧投影待修复，不自动覆盖有效配置。
- 同 revision 但内容 hash 改变：视为外部编辑候选，展示差异并确认；不能自动联网或扩大权限。
- 版本文件缺失但 DB 快照完整：可重建版本文件，记录诊断。

用户修改外部文件和 UI 同时保存发生冲突时，不最后写入者悄悄覆盖；给出差异和选择。预设修改不会更新既有成员副本，只有主动“重新采用模板”创建新 revision。

## 9. 附件发布、保留与清理

### 9.1 导入与不可变对象

1. 从 OS dialog/粘贴/授权 URL 得到受限来源，不使用模型给出的本机路径。
2. 流式写 staging，检查实际 bytes；不为大文件一次性分配 base64。
3. 识别真实内容类型，图片检查尺寸/帧数/解码预算，GIF 限制累计帧成本。
4. 计算 SHA-256，flush，同卷 rename 到对象区。
5. 在 DB 写 attachment 元数据和引用；消息提交前对象必须可用。
6. 未引用对象在短暂保护期后由 GC 回收。

内容 hash 去重是可选优化，必须仍按对象引用和隔离状态管理；不同许可/来源元数据不会因字节相同就合并丢失。

### 9.2 保留策略

默认建议：文本长期保留、聊天图片/文件长期保留直到用户选择清理；缩略图及临时缓存可自动清理。具体单文件、总附件、缓存、导入和导出限制见 [00](00-文档导航与确认清单.md)，用户可以改变。

原始图片、表情收藏、任务未完成和活动备份 pin 优先保护。达到存储上限时先阻止新增/提示清理，不默认静默删除旧文本或用户原文件。

### 9.3 GC

GC 两阶段：枚举无引用且无 pin 的对象 → 标记待删除并再次检查 → 删除对象文件 → 更新 DB 状态。并发引用创建必须阻止 GC 删除刚被重新引用的对象。启动清理过期 staging、孤儿发布对象和失效 pin，所有清理有数量/耗时上限。

附件过期/手动清理保留元数据占位，搜索文本不丢。哈希不匹配显示损坏并隔离，不用看似同名文件顶替。

## 10. 备份格式与流程

### 10.1 可恢复包

建议版本化 ZIP（或后续明确压缩格式），内容包括：

```text
manifest.json
snapshot/chat.sqlite3
config/                        # 与快照 active revision 一致的非敏感配置
objects/                       # 从快照枚举的附件，可选包含
README.txt                     # 自动生成的恢复说明，不是源项目文档
```

默认排除 API Key、临时 provider 会话、缓存、正在写入的 WAL/SHM、运行日志、原 bootstrap 本机绝对路径和包自身所在 backups 目录。不能把旧备份再次递归打包进去。

manifest 必须含：format_version、app/schema 版本、备份 ID、创建 UTC、数据根 UUID、消息范围和数量、对象路径/大小/哈希、配置 revision/hash、排除项、缺失/过期附件列表、是否加密及需要重新绑定的 credential refs。

校验和检测损坏，不代表包来源可信；含秘密加密包是独立可选设计，不仅给 ZIP 设置弱密码。

### 10.2 一致快照步骤

推荐首版在短维护窗口暂停新的数据修改和自动发言：

1. 申请 maintenance gate，停止新消息/配置/附件提交，允许短事务完成；前端输入可保留草稿。
2. 取消未发社交候选；对工具远端 job 保存状态，返回结果暂存，不能继续写入活跃数据。
3. 建立 SQLite online backup 到 staging，完成后执行一致性检查。
4. 从快照枚举 active 配置和附件，建立 pin；附件 GC 暂停。
5. 快照固化后可恢复正常聊天，但快照对象 pin 与不可变配置继续保护至打包完成。
6. 复制快照列出的附件和有效配置，逐项 hash/size 校验，写 manifest。
7. 完成压缩并验证包，再同卷发布正式文件；失败文件不展示为成功备份。
8. 释放 pin 和维护状态，记录备份完成时间。

可以以后改为更长并发备份，但必须保留配置/对象一致性。不直接复制活动 chat.sqlite3，不手工 checkpoint 后假定万无一失。

## 11. 恢复与导入

### 11.1 首版恢复模式

建议只支持“整体恢复到新数据根并切换”，不做任意库合并。默认先备份现有数据，用户明确确认。恢复后成员先暂停，凭据需重新绑定，历史待发任务不自动重提交。

### 11.2 验证步骤

1. 在新空 staging 中读取 manifest 和实际解压流量。
2. 校验格式/版本、条目数量、路径、大小、哈希及禁止类型。
3. 拒绝越界路径、链接、junction、ADS、设备名、归一重复路径和压缩炸弹。
4. 使用可信 bundled SQLite 打开候选库，扩展加载关闭；开启防御/不可信 schema 约束并验证允许 schema。
5. 做 integrity/foreign key 检查和允许升级；未来 schema 不支持时拒绝，而非强行降级。
6. 检查所有对象引用与已声明缺失项；缺失须让用户知晓。
7. 重新生成本机 bootstrap 目标，不使用包内绝对路径。
8. 完整验证后按与迁移相同的 pointer 切换流程激活，保留旧根可回滚。

检验 SQLite 文件也涉及恶意 schema 和畸形数据，不只是“能打开就可信”。导入配置和 SKILL 不自动授权、不自动启用联网。

### 11.3 可读导入/导出

- 导出 JSONL/JSON：稳定 ID、发送者快照、UTC、类型、引用/提及、正文、附件相对引用、撤回占位及格式版本。
- 导出 Markdown/HTML：可读文本和附件链接，输出 HTML 必须转义，不携带可执行脚本。
- 可读记录导入若提供，需单独定义映射与去重，不能当成完整恢复；默认 V1 先做恢复包导入。
- 删除后的数据可能仍在用户自己保留的导出/备份中；应用不能承诺删除所有外部副本。

## 12. 存储目录迁移

### 12.1 状态阶段

`Precheck → Quiescing → Snapshot/Copying → Validating → TargetPublished → PointerSwitched → Reopened → Committed`。

操作日志写在固定 bootstrap 目录，包含源/目标 root UUID、阶段、清单 hash、恢复选择和操作 ID；不能只存在即将关闭的 DB 中。

### 12.2 流程

1. 检查目标本地目录、空闲空间、可写、无嵌套源目录/已有不同根、无网络共享。
2. 目标已存在数据时拒绝直接覆盖，让用户另选或明确恢复流程。
3. 显示将暂停运行和保留源数据；取得用户确认。
4. 获取 maintenance gate，等待短写事务/附件提交结束，暂停返回结果提交。
5. 保存工具状态、停止/取消社交任务，关闭 DB 及相关文件句柄。
6. 复制到目标所在卷 staging，校验 DB/配置/附件；本机 OS 凭据不复制。
7. 在目标卷同卷发布完整目录；不能跨卷 rename 源目录。
8. 采用经验证的 Windows 原子文件替换机制更新 bootstrap，保留 previous 和操作日志；写入/flush 失败不继续。
9. 重开目标，校验 root/schema/引用与 active revision，恢复用户选择的运行状态。
10. 标记 committed，保留源目录直到用户再次确认清理；不是迁移成功就立即删除。

绝对原始路径只保留在固定恢复日志中，正常消息附件使用相对路径，切根无需逐条改写路径。

### 12.3 中断恢复矩阵

| 中断阶段 | 启动选择 |
|---|---|
| Precheck/Copying | 使用源，目标 staging 不活跃，可续传或清理 |
| Validating | 使用源，验证未完成不能切换 |
| TargetPublished 且未切 pointer | 使用源，核实目标后由用户继续切换 |
| PointerSwitched 且未重开成功 | 检查目标，失败恢复 previous；源未删除 |
| Reopened 未 committed | 比对日志/目标 UUID，确认完成或回滚，不双写 |
| Committed | 使用目标；旧根仅作为回滚副本 |

不能同时启动两个根的 actor，也不能在恢复过程中复制 OS 锁文件后误认为仍被占用。遇到锁先查持有进程/有效状态，不直接删除。

## 13. schema 升级与可靠性

- schema_version 和 migration checksum 独立记录。
- 升级前生成可恢复快照；SQL migrations 尽量事务化，耗时索引重建有阶段日志。
- future version 不支持则只读/提示使用新版本，不强行降级。
- DB 损坏时保留原件，提供导出/恢复流程，不自动创建同路径空库。
- disk full/busy/IO error 显示 typed error，草稿和当前配置不丢。
- 定期 checkpoint 依据 WAL 实际增长/空闲机会进行，不能无限长 read txn。
- 文件删除不承诺物理擦除；SQLite 页、WAL、SSD、备份与 OS 缓存可能保留历史痕迹。

## 14. 数据层验收

1. 10 万文本消息与混合附件的分页、中文搜索及索引大小基准。
2. COMMIT 前后各时刻崩溃，消息和事件不会丢一致性或重复。
3. 撤回后 UI、引用、FTS、摘要/记忆不回流旧文。
4. 配置投影/版本发布/DB 激活各阶段中断，恢复版本明确。
5. 备份中消息/配置/附件提交和 GC 冲突，恢复包完整。
6. 恶意 ZIP 路径/链接/大小和恶意 schema 被拒绝，用户数据未被覆盖。
7. C→D 跨卷、中文/长路径、目标 ACL、杀毒占用及每迁移阶段强制中断。
8. 默认备份不含密钥；跨设备恢复可重新配置且不会自动补跑付费任务。
9. 日志和事件保留不会形成无限第二份聊天数据库。
10. 任何失败不删除用户原文件、不静默覆盖现有根。
