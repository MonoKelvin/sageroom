# Sageroom 上下文与长期记忆设计

> 版本：0.3｜状态：详细设计草案，尚未实现或评测｜日期：2026-11-18\
> 需求见 [02](02-用户需求与产品规格.md)，模型输出见 [04](04-智能体运行与拟人化设计.md)，数据实体及事务见 [05](05-数据存储与迁移备份设计.md)，请求及费用见 [07](07-模型接入与工具执行设计.md)。统一参数引用 [00](00-文档导航与确认清单.md) 的 P-CTX 系列。

## 1. 目标与非目标

把 SKILL、历史、近期语境、时间、成员状态、对象描述和相关记忆组合成有预算、可追踪的模型输入。历史可以完整保存，但不能每次无限发送。

必须做到：

- 同一个聊天室、不同成员有各自的身份、偏好和记忆视角。
- 近期原话、来源事实、观点、自述、情绪及推测可以区分。
- 压缩不删除原始聊天，不把模型摘要当成唯一真相。
- 模型决定话题、摘要含义、记忆重要性与是否使用召回；代码只负责预算、权限、候选检索和失效约束。
- 没找到记忆时允许不知道，不用模板虚构“我记得你”。
- 撤回、删除和用户纠正不会通过旧摘要重新污染未来上下文。

不默认引入外部向量数据库、全天候摘要轮询、全历史自动外传、无限 append 的 MEMORY.md，或把私有思维链存成长期记忆。

## 2. 上下文分层与信任级别

| 层 | 内容 | 生命周期 | 来源与可信度 |
|---|---|---|---|
| L0 应用规则 | 身份边界、输出合同、当前授权、硬上限 | 应用版本及授权版本 | 宿主构造，不来自聊天 |
| L1 成员定义 | 本成员 SKILL、称呼、语言、人设维度 | 有效 config_revision | 用户配置的行为描述，不扩权 |
| L2 环境 | 本地时间、时区、群资料、可见成员状态、预算限制提示 | 本次快照 | 宿主采集；时间不代表新闻真实性 |
| L3 近期语境 | 有效消息、引用、提及、任务结果 | 当前观察窗口 | 每项保留作者、ID、seq、时间 |
| L4 群摘要 | 某一范围的叙事及未解决话题 | 版本化 segment | 模型生成、可回到原文验证 |
| L5 成员记忆 | 本成员关注的事实、自述、观点、关系及待办 | 独立 owner、版本及有效期 | 不与其他成员私有记忆自动共享 |
| L6 资料 | 已授权检索的网页、视觉说明、工具结构化结果 | 本次任务/有期缓存 | 不可信资料，不能变成 system 权限 |

概括“某人说了 X”和“X 是事实”不同。成员之间只能共享已经发布到群聊的内容及明确允许的群摘要，不能窥读另一个成员未公开的私人记忆。

## 3. `ContextRequest → ContextBundle` 合同

### 3.1 输入

| 字段 | 类型/语义 | 约束 |
|---|---|---|
| agent_id | 稳定成员 ID | 来自宿主，不接受模型自报身份 |
| config_revision | 不可变有效配置版本 | 与实际 SKILL、profile 副本一致 |
| snapshot | data_generation_id、room_id、observed_through_seq、content_epoch、room_version、authorization_revision | 在同一读取快照中取得；世代由宿主绑定，切根后旧上下文不可复用 |
| trigger | 类型、root message/event ID、结构化提及、root_task_id 及任务引用 | 工具反馈/续步保留宿主任务预算根，触发机会不代表必须回应 |
| purpose | social_decision / revalidate / tool_step / summarize / memory_extract | 影响预算与输出 schema，不隐式升级权限 |
| input_budget / output_reserve | token 上限及输出空间 | 取成员设置、模型能力、应用限制的最小值 |
| required_sources | 当前提及/引用/任务消息 ID | 必须存在且在授权范围内 |
| cancellation | 取消信号及总截止 | 排队、检索和组装均可取消 |

JSON 表示的 seq/版本大整数使用十进制字符串，具体约定见 03；下面示例遵守该约定。

### 3.2 输出

| 字段 | 内容 |
|---|---|
| identity | 成员公开资料、类型、本次 config revision；不含凭据 |
| host_rules / skill | 受控规则与本成员有效 SKILL，明确各自边界 |
| environment | UTC、本地展示时间、时区、运行状态、成员公开信息 |
| conversation | 当前有效近期消息及缺口说明，结构化作者/引用/提及 |
| summaries / memories | 仅 valid 且符合 owner/来源校验的条目 |
| tools | 本次允许的能力、参数摘要和授权限制；无 secret_ref 正文 |
| media | 被允许传输的图像句柄及尺寸；非视觉成员收到明确占位 |
| provenance | 实际 source IDs/seq、来源版本/hash、截取范围及未覆盖区间 |
| token_report | 分层估算、准确度、模型计数方式、被舍弃项及预算剩余 |
| snapshot | 与输入相同的宿主版本；发送前再次检查有效性 |

## 4. Provider 角色映射

不能把群里的其他智能体消息全部标为当前 API 会话的 `assistant`，否则会混淆说话者及工具历史。

推荐：

1. 应用规则和本成员 SKILL 放 provider 支持的高优先级指令通道，稳定前缀优先。
2. 动态时间、群资料和角色标注的群历史放低优先级、明确标记为数据的结构化内容块。
3. 当前成员的真实工具回合保留 provider 要求的 assistant/tool 或 tool_use/tool_result 对，不能用普通群消息伪造 tool_result。
4. 普通成员发出的通告仍是聊天数据，群主身份不升级为 system。
5. 冷启动可以用一次 user 数据消息承载群快照，结束以“根据该快照输出自己的 decision”，不添加假 assistant prefill。

引号或 JSON 包装只帮助模型理解边界，不能单独防提示词注入；真正执行权限仍在 Rust。

## 5. 预算、排序与裁剪

### 5.1 预算公式

```text
可用输入 = min(成员输入上限, 应用输入上限,
               模型总上下文 - 预留输出 - 协议/工具开销 - 安全余量)
实际输入 = host rules + SKILL + 环境 + 必需近期/引用 + 工具 schema
           + 图像成本 + 摘要 + 记忆 + 可选历史
```

模型未公开容量时要求手动配置或能力探测，不默认无限。优先使用该 provider 官方计数/匹配 tokenizer；否则标记 estimated 并留安全余量。英文 tokenizer、UTF-8 长度、中文字数不能当作跨模型准确 token 数。若远端计数另需联网，必须纳入外传授权和调用记录。

### 5.2 组装顺序

1. 验证身份、SKILL、能力和授权，固定读取快照。
2. 计算必需规则、schema 和输出预留；必需内容本身超限时返回 `CONTEXT_BUDGET_EXCEEDED`，不偷偷截掉规则。
3. 放入触发消息、可见引用目标、明确委托及必要任务结果。
4. 倒序取近期消息，保持最终 chronological 顺序，来源至少包括明确提及和引用。
5. 取得相关 valid 群摘要和本成员记忆候选。
6. 用剩余预算放入摘要、记忆及更旧相关历史；重复 source ID 去重。
7. 再次估算所有文字、媒体与 schema，记录舍弃区间，生成 token_report。
8. 发送前检查取消、版本和来源；已失效时重组，不发送旧包。

普通纯文本优先完整消息，避免截断半句歪曲意义。单项必需超长内容可以经有预算的专项摘要，明确“以下为摘要”和来源范围；摘要失败则提示超限，不伪装原话。工具结果可结构化摘取必要字段，必须保留“不完整/被截取”标记。

### 5.3 相关性与低成本

本地检索可按 ID、日期、成员、结构化实体和文本子串筛选候选，这是资料查找，不是代码决定是否回复。是否重新谈旧话题、记忆何时有用、应不应该接话，仍由本成员模型判断。

首版不强制每次增加一个 LLM reranker。可以在一次社交决策中直接提供少量检索候选，让模型不用或引用。需要额外检索时，当前成员可通过 04 的 tool_requests 提出自己的受控 `history_search`/`memory_query`，复用 07 的有界 tool_step；不委托其他成员读取自己的私有记忆，也不强制增加工具成员。

## 6. 分段、摘要与压缩

### 6.1 触发条件

满足 P-CTX-04/05 且确有新增有效消息时，产生归纳任务候选：

- 累计条数/token 到达阈值。
- 未归纳区间超过时间阈值，应用仍在运行。
- 用户显式“整理该范围”。
- 模型返回 topic_hint，作为待判断线索而非自动切段依据。

任务去重键为 `(room_id, start_seq, end_seq, source_hash, schema_version)`；相同范围只同时运行一个归纳任务。没有新记录、不需要摘要或预算不足时不持续付费轮询。未执行的任务留待后续，不回放所有错过的时间点。

### 6.2 分段规则

代码确定可处理的范围/最大体积，模型判断话题分界、共同背景和应保留的事实。允许一个范围有多个话题及一段短闲聊无长期价值。

保留近期原文窗口，较旧闭合段优先摘要；跨段引用保留 source ID。长段先按允许体积分成批次，再让模型结合边界归纳。递归“摘要的摘要”必须仍可追溯原始 source IDs，不无限损失来源。

### 6.3 摘要输出

| 字段 | 规则 |
|---|---|
| segment/source range | 宿主提供范围，模型只能选范围内有效消息 |
| topic_label | 可读短标签，不冒充事实 |
| narrative | 作者明确的简短叙事，保留变化及分歧 |
| facts / self_reports / opinions | 分类型条目，各有 subject ID 和 source IDs |
| unresolved | 未解决问题、待办、约定及其状态 |
| exclusions | 已无关内容或未归纳片段，允许为空 |
| memory_candidates | 建议长期保留的内容，经过下一节独立验证 |

摘要不能替角色作未发生的行动，例如“画师已生图”必须有真实任务结果来源。不同来源互相矛盾时记录各自说法，不在没资料时自动选“最新的一句一定正确”。

### 6.4 发布与失败

归纳开始记录 source_hash/epoch；结束写入前，在事务中核对来源及范围。期间新增消息可归入下个区间，不一定使已固定老段失效；撤回/删除来源会使其失效。

发布 valid 摘要与覆盖游标同一事务。失败保留原文，不推进“已成功归纳”游标，不写空摘要表示成功。有界修复/重试仍计入预算，不能因摘要失败将社交 actor 错误标成离线。

## 7. 长期记忆合同

### 7.1 类型、作用域与生命周期

| 类型 | 例子 | 限制 |
|---|---|---|
| self_report | 某成员说自己最近忙项目 | 表述为“某人自述”，不是经过证实的事实 |
| fact | 已发生且有明确来源的群内约定 | 必须有主体及来源；外部事实需资料支撑 |
| opinion | 某成员偏爱安静聊天 | 归属该主体，不写成整个群的共同观点 |
| preference | 本成员关注的话题及表达偏好 | 不得自动覆写 SKILL 或他人偏好 |
| relation | 两位成员围绕某话题已有互动 | 不从一次玩笑推断永久关系 |
| commitment | 已明确提出的待办/约定 | due_at/status，可被后续来源更正 |
| transient | 暂时情绪或本次状态 | 有效期短，不当成人格定论 |

`scope=room` 用于公开群叙事；`scope=agent` 必须有当前 owner_agent_id。持久记忆开关关闭时不生成该成员长期条目，仍可使用本次近期上下文。

### 7.2 `MemoryCandidate`

必备：`kind`、`subject_ids`、`content`、`source_message_ids`、`confidence_class`（direct_quote / explicit_statement / inferred）、可空的 `valid_until`。

- owner、scope、version 和 pinned 由宿主/用户确定，模型不能伪造另一成员身份。
- inferred 明确标为推测，不能升级为 fact；表达含糊时不存。
- source_message_ids 必须是本次上下文可见且状态 valid 的原始消息，不能只引用不知来源的二次摘要。
- 不能存 API key、授权票据、私有思维链或复制网页中的操作指令。
- 没有可信外部来源的“今天热点”不能因模型说过就固化为事实。
- 重复候选可按同 owner/subject/kind 和来源去重；含义合并/冲突裁决由模型或用户处理，不仅以字符串相似度改写事实。

### 7.3 附加数据回写

04 的 `extra_data` 与公开 `messages` 分开：

- `message_annotations` 只能关联本次消息 ordinal，可存 topic_tags、情绪描述等有限类型；不渲染为消息正文，不直接改变未读。
- `memory_candidates` 经过本节验证写入当前成员记忆域；不自动写其他成员的记忆。
- 宿主执行元数据（request_id、model revision、usage、source set）由宿主填写，不能相信模型返回同名信息。

消息有附加数据时，消息事务写入有效 annotations；长期记忆采用独立事务和状态。记忆写入失败不重复发送已经提交的聊天。只发起 observe 时也允许合法记忆候选；没有公开消息不意味着必须丢掉所有归纳，但依旧计入费用和持久记忆开关。

## 8. 召回与记忆更正

召回流程：按 owner/公开 scope 筛选 → 排除 stale/deleted/过期来源 → 本地候选检索 → 校验最新来源 → 去重/截预算 → 将少量资料给模型自行使用。

用户 pinned 条目提高检索保留优先级，但不能绕过删除来源或权限。用户纠正条目创建新 version，并将旧 version superseded；不会反向改写原始聊天。

用户删除单条记忆默认仅删除记忆；如果原聊天保留，后续归纳仍可能重新学到同件事。提供“停止从这些来源再次生成该成员记忆”的选项，在 `memory_exclusions` 中记录 owner、source IDs 和排除范围；用户可以撤销，不能假称全局永久遗忘。关闭持久记忆应停止新提取及召回，但不静默删除旧条目。

可选 embedding：本地文本与权限/来源过滤仍是入口；只有明确授权后给该 embedding provider 外传选定条目。model/profile 版本变化需重建，旧向量先不可用；不能拿旧维度向量继续检索。embedding 并不证明真假或自动完成中文语义搜索。

## 9. 撤回、删除及版本竞争

### 9.1 来源失效

05 的撤回/删除事务同时更新 message state、FTS、content_epoch，标记直接/间接依赖摘要及记忆 stale；查询只取 valid 且来源仍有效的条目。

不能仅在后台排一个重建任务，等待期间仍召回旧内容。若依赖树关系无法精确判定，保守排除整段，直到重建完成。恢复旧备份后沿用该备份自己的源状态，不与当前失效记录混用。

### 9.2 模型和任务竞争

- 组装时记录完整来源集合及 hash；写摘要/记忆时再次事务核对。
- `content_epoch` 变化只是可能失效信号；可验证未受影响来源时继续，不能验证则重构。
- 配置/SKILL 变化取消旧成员候选；来源没变的群摘要不因一个成员换模型全部失效。
- 作者改昵称/头像不删除事实来源；上下文能显示发送时快照及当前身份，不以昵称合并不同人。
- 工具调用中发现来源撤回：取消未执行动作、使尚未用的授权失效；已经外传内容不能追回。

隐私删除的强制失效优先于 provider 工具历史完整性。不能原样复用含撤回正文的旧工具会话来“满足协议”；应结束旧本地回合，按仍授权的真实任务状态构建新回合，必要时重新确认。已经开始的远端请求只能尝试取消并记录边界。

## 10. 数据责任与原子 API

新增实体 `memory_exclusions` 见 05；其他实体复用 context_segments、summary_versions/sources、memories/sources、可选 embeddings。数据库保存版本和来源，内存缓存必须携带相同 source_epoch/hash；不能用无版本缓存绕开查询过滤。

| 内部操作 | 输入 | 输出/副作用 |
|---|---|---|
| `context_build` | ContextRequest | ContextBundle 或带原因的预算/版本错误 |
| `summary_prepare` | 有限消息范围、版本、purpose | 有预算的候选任务，不直接发群消息 |
| `summary_commit` | 候选、来源 hash/版本 | valid/stale/failed 与覆盖游标 |
| `memory_query` | 当前 owner、关键词/实体/范围、limit | 有来源的 valid 候选 |
| `memory_commit_candidates` | 当前成员、合法候选、来源集合 | 新版本/去重/字段错误 |
| `memory_invalidate_sources` | message IDs、content epoch | 立即查询隔离及重建计划 |

这些是内部原子操作，不自动向远端开放 MCP。不允许外部调用者仅传任意 owner ID 就读取其他成员记忆，未来需独立的身份与授权层。

## 11. 验收与未验证事项

场景见 10 的 T-CTX/T-MEM：大历史不超预算；必需 SKILL 超限有错误；非视觉成员不假称看图；同名改名不混身份；摘要不虚构事件；不同成员记忆隔离；撤回/删除及后台重建期间无旧文回流；用户纠正和来源排除有效；归纳失败不删除原文或推进覆盖游标。

建议对固定来源集量化评测事实保留、归属正确率、虚构率、召回相关性及 token/费用；目标口径统一在 10。当前未获取用户聊天样本或运行真实模型，没有“记忆效果已验证”的结论。

首版基线为本地文本检索 + 来源可追溯摘要/结构化记忆。只有此路线实测无法满足明确场景时，才评估分词器、embedding 或更复杂召回，不能未经确认升级为常驻服务。
