# Sageroom 安全、隐私与可靠性设计

> 版本：0.2｜状态：设计草案，未进行安全测试或故障实测｜日期：2026-11-18  
> 模块及接口见 [03](03-总体架构与模块合同.md)，数据维护见 [05](05-数据存储与迁移备份设计.md)，模型/工具执行见 [07](07-模型接入与工具执行设计.md)，测试见 [10](10-测试验收与性能评估.md)。统一策略、参数及未确认项见 [00](00-文档导航与确认清单.md)。

## 1. 安全目标及保护边界

保护 API Key、聊天/记忆、用户原文件、工具授权、费用和存储完整性；防止模型或网页通过候选动作获得任意本机操作权。

本地优先不是完全离线，也不是操作系统沙箱。首版普通 SQLite/附件不默认加密；Credential Manager 不阻止所有同账户恶意程序；不承诺抵御 OS/用户账户完全被接管、SSD 物理恢复或所有 provider 数据保留。

安全限制可以拒绝越权/过费/超时动作，但不替模型作“该不该接话”的社交判断。危险能力不因拟人化、群主身份或“用户之前授权别的任务”自动开放。

## 2. 资产、输入与信任边界

| 资产/边界 | 风险 | 主要控制 |
|---|---|---|
| WebView → Rust IPC | 前端被注入后任意调用、伪造 actor/路径 | 最小窗口 capability、自定义 command ACL、后端输入与业务授权 |
| Rust → 模型/工具服务 | 内容/密钥发错端点、无限收费 | 明确 endpoint 绑定、TLS、grant、原子预算与请求归账 |
| 模型 JSON → 动作 | 非法引用、群主越权、任意工具 | 类型/schema、ID 范围、当前权限、预算和来源重校验 |
| 网页/附件/聊天 → 提示词 | 注入新指令、虚构任务授权 | 明确数据边界，真正权限不在提示词内执行 |
| 用户文件 → 暂存/预览 | 路径逃逸、恶意解码、启动程序 | 受限句柄、大小/像素预算、安全格式和不自动执行 |
| 恢复包 → 数据根 | ZIP 越界、恶意 SQLite、覆盖原数据 | 新空 staging、严格路径/资源检查、允许 schema、验证后切根 |
| 数据库/文件系统 | COMMIT/文件发布分裂、磁盘满 | 发布顺序、幂等、恢复日志、完整快照 |
| 日志/导出/备份 | 泄漏正文/密钥、递归打包旧备份 | 默认脱敏、排除秘密、范围预览、无自动上传 |

SKILL、模型响应和导入配置都是待验证输入；配置文件内写“有权调用工具”不形成授权记录。

## 3. 权限模型

### 3.1 身份分离

- 本地用户拥有应用管理权，是否担任群主另有字段。
- 当前群主仅具有 02 的四项群管理权，不带模型、密钥、删除他人消息、预算或文件权限。
- 智能体身份由宿主 envelope 绑定，前端/模型不能传 actor_id 冒充他人。
- 工具权限由本地用户建立，可按成员、工具、endpoint、数据范围、单位和有效期收紧。
- 资料自主修改仅针对自身获准字段，默认建议关闭；不允许改 SKILL 的安全规则、工具授权或模型目的地。

### 3.2 执行时校验

校验发生在排队前和执行/提交前：owner 可能变化、grant 可能撤销、来源可能撤回、配置可能换版本、额度可能被其他成员消耗。

一次许可绑定具体 task/参数/数据 hash 和 endpoint；新参数不能用旧票据继续执行。长期许可只涵盖明确范围，不是无限授权。权限撤销阻止后续步骤，已执行的远端行为可能无法撤销，记录实际状态。

本地用户选“重新上线”仅申请诊断测试/启用，不同时批准未知联网、生图或上传所有历史。

## 4. Tauri / WebView / IPC

### 4.1 自定义 command 与窗口权限

2026-11-18 使用 Context7 核实 Tauri v2 capabilities：注册的自定义 command 默认对窗口/webview 可调用；插件权限不自动为应用自定义 command 建立最小白名单。实现需用 AppManifest/应用 permissions/capabilities 显式约束，并在 command 内检查来源和业务授权。

建议窗口边界：

| 来源 | 可调用范围 |
|---|---|
| 主聊天室本地 UI | 快照、聊天/阅读、受限附件、成员详情、任务查看和明确用户确认 |
| 本地设置窗口 | 配置、secret 写/删/status、运行授权、维护操作、诊断导出 |
| 远端网页/嵌入内容 | 不赋予应用 IPC 或文件能力，不在有权限 WebView 中导航 |
| 模型输出 | 无直接 IPC 权限，仅进入 04 的候选校验器 |

窗口标签只限制入口，不等于能识别“真实用户刚点了按钮”。XSS 落入获权窗口仍可能调用已有权限；因此同时需要 CSP、安全渲染、最小功能和危险操作的可信摘要/确认，而不能宣称 capability 完全解决 XSS。

### 4.2 CSP 与内容渲染

- 发布版启用 CSP，具体源按选定 Tauri/WebView 的实际本地资源协议生成并验证，不照抄 `unsafe-eval` 或 `*`。
- 浏览器不直接调用模型提供方，不需要向任意域名放开 connect-src。
- 默认禁止 raw HTML、脚本、iframe、远端图片/音频嵌入和跟踪像素。
- Markdown 使用成熟解析器的受限子集和 sanitization；纯文本 HTML 转义。
- 外链只允许获准 http/https，屏蔽 javascript/data/file 等可执行或本机协议；用户显式打开外部浏览器，不自动访问。
- 对长文本、代码和大量链接限制渲染工作，不因模型生成无限内容阻塞 UI。

development 环境可能允许本地热更新连接，但发布配置不能继承 dev 例外。所有主要窗口、原图预览和设置都需要独立测试。

## 5. 凭据与 endpoint 绑定

推荐 Windows OS Credential Manager，经 Rust SecretStore 访问；精确 keyring/store 版本在 01/11 的冻结和编译验证中确定。

- 前端可以输入、替换、删除 key，保存后只能得到 status/masked metadata；没有 secret_get 明文接口。
- 密钥不进入成员副本、SKILL、上下文、普通 DB、domain_events、默认备份或诊断包。
- 请求时 Rust 解析 secret_ref，加入对应 adapter 的鉴权位置；模型无机会读取或指定 header。
- 更新 key 和普通模板保存是分开的动作；影响共用引用必须提示。
- endpoint fingerprint 按协议、规范化 origin/路径前缀及必要账户域绑定。端点变化先暂停，重新测试/授权。
- Redirect 不能把 Authorization/x-api-key 继续转发到新 origin；模型 API 默认不自动跨 origin 跳转。
- secret_set/delete 失败不能把 UI 展示成已保存/已移除；先完成 OS store 动作并按可恢复顺序更新状态。

DPAPI 用户/设备绑定数据不能宣称随普通备份跨设备可用；Stronghold/整库加密是可选路线，需要解锁、KDF、密码遗失和移动平台重设计。默认排除 key 的备份恢复后重新绑定，不从安装包暗带共享 key。

## 6. 网络授权和 URL 安全

### 6.1 区分两种网络路径

1. **模型 endpoint**：用户配置并明确授权；本地/指定内网地址是可单独批准的例外。
2. **搜索正文/生成文件下载**：由不可信外部 URL 驱动；默认只访问公开网络，不继承模型内网例外。

URL 来源真实不代表安全，搜索结果、HTML 链接和模型候选都必须校验。grant 不能只按字符串域名判断后信任任意重定向。

### 6.2 抓取/下载规则

- 只允许 http/https，默认 HTTPS；拒绝 URL userinfo、非法端口、混淆地址、file/data/自定义协议。
- 解析 DNS 后验证所有候选 IP，拒绝 loopback、私网、链路本地、组播、未指定地址和云元数据目标；IPv4/IPv6 和映射形式都覆盖。
- 每次重定向重新校验 scheme、host、IP、端口及授权，不能只检查第一个 URL。
- 连接目标必须与已检查解析结果一致，防止 DNS rebinding；HTTP 客户端代理和 DNS 行为也纳入测试。
- 不转发模型凭据、浏览器 cookie、用户登录态或无关 header；不自动登录私人网页。
- 先限制流读取和解码体积，再解析/保存；Content-Length 和 Content-Type 只能作为提示。
- 网页 text/html 提取不执行 JS、不调用页面脚本、不自动下载附属资源。

建议抓取上限：单网页解压后 2MiB、单次抽取 20000 Unicode 字符、最多 5 次重定向；结果不完整须标 truncated。媒体下载使用 P-MEDIA-01/02，并限制解压/解码后成本；不能以“小压缩包”为无限解码理由。这些是 09 所维护的待确认网络安全参数，不在其他文档另设不同值。

## 7. 附件与内置素材

### 7.1 本地文件

OS dialog/粘贴/拖放产生受限句柄，Rust 读取该明确对象；不接受模型或任意前端提供的裸路径访问硬盘。保存/另存是单独显式用户操作，只写选定目标，不静默覆盖其他文件。

- 原文件名只显示，不直接拼接目录；object ID/hash 生成存储路径。
- 检查实际字节、真实类型、尺寸、帧数和工作池预算。
- 图片/GIF 格式白名单和维护中的 decoder；异常隔离，不能半解码仍显示成功。
- SVG/HTML 等带主动内容不直接嵌入 WebView；需要支持时经独立安全转码或仅作为普通文件。
- 普通文件可安全存储但不自动执行；默认不提供脚本/可执行文件一键启动。
- 大文件流式复制，不先全量转 base64；清理只作用于应用创建且无引用/pin 的对象。

用户明确选择删除应用附件也不能删除原始盘上的源文件。表情收藏、头像、任务和活动备份引用独立计数。

### 7.2 内置 emoji / 颜文字 / 表情包

系统原生 emoji 不要求下载字体；选择器源码许可与图片资产许可分别核查。颜文字可独立编写小数据集；静态/GIF 表情须自编/自制或取得明确授权，不从 QQ/微信截图集合直接批量复制。

素材清单至少记录 ID、来源、作者、许可证、是否允许分发/修改、署名要求、文件 hash 和取得日期。第三方库 MIT 不代表其关联表情图片也是 MIT。首版确需内置表情包，不能把“暂无许可资源”或空收藏 tab 视为完成；落实在 11 的素材工作包中。

第三方自然聊天 SKILL 同样核查原文和许可证，先人工阅读差异，不自动执行脚本、联网安装或注入工具权限。

## 8. 恢复包与不可信 SQLite

### 8.1 ZIP / 路径

解包前新建本操作的空 staging，不从包目录执行脚本/构建工具。逐项流式读取：

- 拒绝绝对路径、盘符、UNC、`..` 越界、symlink/hardlink、junction/reparse point。
- 检查 Windows ADS、设备名、尾随点/空格、大小写和 Unicode 规范化后重复项。
- 验证父路径始终在 staging，防止写入时链接替换导致 TOCTOU。
- 对实际展开字节、条目数、单项大小应用 P-IMPORT-01，而不是信压缩头。
- 不递归解开嵌套压缩包，不执行 README/脚本，不信任包内绝对 bootstrap。
- manifest hash/sha256 检测损坏，不是来源认证；配置中 grant/key 状态不自动激活。

### 8.2 SQLite 验证与允许 schema

使用可信 bundled SQLite，候选库仅在 staging 访问；禁扩展加载，打开连接后设置 defensive/trusted_schema OFF 等可用防护、SQL/内存/时间上限，不注册有副作用的自定义 SQL 函数。

先检查 format/schema version 和应用允许的 tables/indexes/triggers/views/FTS 定义，再做 integrity_check、foreign_key_check、数据大小及 ID/enum/引用约束。不执行包内 migration SQL，升级脚本只能来自已安装的应用版本。

`trusted_schema=OFF` 不等于所有恶意 schema 都安全，hash 匹配也不保证 engine 无漏洞；采用安全更新的引擎、允许 schema、资源预算和隔离暂存共同控制风险。若 FTS 使用触发器，只允许已冻结的应用定义，不让包内任意 trigger 成为本地执行入口。

验证通过后按 05 整体恢复到新根，旧根保留；恢复成员默认暂停、凭据重新绑定、未完成付费任务不自动再创建。未知 future schema 明确拒绝，不降级或创建空库。

## 9. 提示词注入与模型输出验证

校验顺序：完整 JSON 解析 → schema/枚举/大小 → 来源 ID 与同 room → 目标所属/权限 → 参数及 tool grant → 预算/版本/取消 → 执行事务。

- `system:`、群公告、网页中“忽略所有规则”均作为数据，不取得权限。
- 模型不能返回自由 command、SQL、shell、任意路径、secret_ref 正文或另一成员身份。
- 04 的 profile_patch 只改自身白名单，extra_data 只写有限 annotations/记忆候选。
- 结构合法但来源撤回/授权变化同样拒绝。
- 在日志记录允许/拒绝原因码，不记录恶意原文的密钥或私有思维链。
- 不追求“用一段安全提示词彻底防注入”；即使模型被骗，执行器也不能越权。

工具输出和 provider 资料也视为不可信，不能因为由可信服务获取就直接执行其附带脚本。

## 10. 时间、预算、幂等与故障恢复

### 10.1 时间可信度

同一进程内，撤回和相对计划使用单调时钟；UTC 仅作展示、持久截止和恢复线索。系统时间回拨不能延长 120 秒撤回窗口，模型不得自报发布时间。

重启时若能通过已验证的同一 OS 启动会话 uptime/时间基准可靠计算真实已逝时间，继续使用原截止；若发生重启机器/异常时钟或无法确定，保守拒绝旧消息撤回并展示原因，绝不重新给予 120 秒。该重启降级需在 Q-04 生命周期评审确认并做 T-TIME 测试，不承诺跨重启精确可信时间已实现。

唤醒过期合并为一次最新决策，不重放每个 tick。日预算持久记录窗口与已消耗值，时间异常进入保护/确认，不允许通过改日期清零配额。重置按 00 的 UTC 日窗口，UI 显示本地重置时间。

### 10.2 故障责任

| 故障点 | 处理与恢复 |
|---|---|
| DB COMMIT 前崩溃 | 不显示已发送，恢复后保留草稿/重试幂等键 |
| COMMIT 后广播前崩溃 | 通过持久事件/快照恢复，unique 防重复消息 |
| 对象发布后消息失败 | 孤儿对象有暂时保护，后续 GC；原文件不动 |
| 配置 DB 激活后投影失败 | 按有效 DB snapshot 修复，不悄悄回退配置 |
| 迁移目标复制/切指针失败 | 按阶段日志选择旧根或验证目标，禁止双写 |
| 模型故障耗尽重试 | Offline 和一次昵称标记，提供诊断/换模型入口 |
| 暂停/限额 | Paused/Protected，不归为 provider 离线 |
| 付费创建后响应丢失 | ResultUnknown，remote ID 查询，不重提相同付费请求 |
| 磁盘满/库损坏 | 保留原库，明确恢复模式，不新建空库遮掩 |

工具结果已生成但群消息写入失败，重试的是本地落地/发布，不重新生图。所有自动动作和用户写操作有幂等键；本地幂等不是 provider 付费幂等。

## 11. 隐私、日志与数据删除

默认不启用产品遥测、崩溃正文上传、外部分析或诊断自动发送。若以后新增遥测，需要独立知情选择、最少字段和关闭入口，不以“提升体验”默认开启。

临时详细日志需用户主动开启、选择范围和有效期；仍不记录 API Key/鉴权 header/思维链。导出前预览字段和脱敏结果，文件只落本地。P-LOG-01 管轮转，不能从异常 raw response 未审查地复制 provider body。

删除的层次：

1. 当前 UI/查询不可见：事务 tombstone。
2. 未来模型输入不包含：引用、FTS、摘要/记忆/缓存同步失效。
3. 本地附件释放：无引用/pin 时受控 GC。
4. 物理痕迹：SQLite 页、WAL、SSD、OS 缓存可能仍有，不能承诺彻底擦除。
5. 外部副本：用户备份/导出、provider 请求/日志及已展示系统通知不能保证自动追回。

备份恢复可能使旧备份中的消息再次存在，恢复前明确提示该边界。用户删除记忆但保留聊天时的重新提取选项见 06，不误称永久全局遗忘。

## 12. 发布与验收门槛

冻结依赖/资产版本和许可；锁文件、安装包和 schema migration 有可复现来源。不要把下载内容目录当执行脚本目录，不为缺资源绕过 hooks、签名或安全检查。

发布包必须验证：没有凭据/真实聊天/个人路径、CSP 为发布策略、窗口 capability 收紧、模型私有数据不进日志、安装态通知及后台生命周期正确。自动更新/签名策略若加入开发范围，单独评审，不把修改共享发布配置视为文档授权。

测试矩阵见 10 的 T-SEC/T-DATA/T-TIME/T-MODEL；出现密钥泄漏、越权工具、旧文回流、备份损坏或重复付费均阻断发布，不能只降为待优化。
