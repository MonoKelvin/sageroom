# Sageroom 总体架构与模块合同

> 版本：0.2｜状态：待确认的设计基线｜日期：2026-11-18  
> 推荐技术证据见 [01](01-技术调研与选型评估.md)；运行细节见 [04](04-智能体运行与拟人化设计.md)；数据见 [05](05-数据存储与迁移备份设计.md)；接口见第 8～10 节。

## 1. 架构目标

1. 前端不持有 API Key、不负责后台计时、不直接写数据库。
2. 每个成员拥有独立状态、SKILL、有效配置版本、上下文游标和可取消任务。
3. 模型决定社交行为，宿主负责能力、权限、时间、费用、并发和持久化正确性。
4. 模块只通过明确输入输出协作，不要求 UI 理解模型协议，也不要求 provider 理解聊天布局。
5. 支持单机完整生命周期：启动、隐藏、暂停、睡眠恢复、退出、崩溃恢复、备份与迁移。
6. 首版不引入服务端、消息中间件、Node 常驻 sidecar、独立向量数据库或每成员进程。
7. 凭据、网页、模型返回、附件和导入文件均通过各自信任边界。
8. 群主权限只用于群名、群参数、@所有人、通告，不改变普通聊天地位。

## 2. 系统边界

```text
┌────────────────── 本地设备 ─────────────────────────┐
│ React WebView                                        │
│   聊天/设置/附件预览/任务状态                         │
│          │ AppCommand / AppEvent                     │
│          ▼                                           │
│ Tauri Rust                                            │
│   IPC Gateway → 应用用例 → 领域模块                   │
│                        ├─ ChatService                │
│                        ├─ GroupService               │
│                        ├─ AgentSupervisor + actors   │
│                        ├─ ContextAssembler / Memory  │
│                        ├─ ModelGateway / ToolRunner  │
│                        ├─ Budget / Authorization     │
│                        ├─ Storage / Attachment       │
│                        └─ Notification / Lifecycle   │
│                               │                      │
│   SQLite DB  不可变配置快照  附件目录  OS SecretStore │
└───────────────────────────────┼──────────────────────┘
                                │ 明确授权的网络请求
                                ▼
                       LLM / 图片 / 搜索提供方
```

远端模型没有直接 IPC 权限。模型只能返回候选动作，由 Rust 校验后执行；不能让模型 JSON 直接映射成任意 Tauri command 或 SQL。

## 3. 关键架构决策

| ADR | 推荐决定 | 原因 | 可变条件 |
|---|---|---|---|
| ADR-01 | Tauri 2 + React/TS + Rust | 满足指定技术与本地能力 | 仅用户主动改变路线 |
| ADR-02 | actor 是同进程异步任务，不是每成员进程 | 行为独立、低资源和生命周期简单 | 确需进程/权限隔离时重新设计 |
| ADR-03 | 单 SQLite + 专用 rusqlite 线程 | 复用事务、索引与备份 | 团队已有 SQLx 强约束时整体替换 |
| ADR-04 | Rig 条件采用，窄 provider adapter 补差 | 尽量复用而不丢失协议控制 | 关键能力 PoC 失败后选择窄原生层 |
| ADR-05 | 文件是编辑/交换载体，已激活快照是运行基线 | 满足成员独立文件，又防双写歧义 | 不允许文件未校验直接覆盖 runtime |
| ADR-06 | 配额与权限是宿主硬保护 | 避免风暴、越权和费用失控 | 用户可调数值，模型不能自行调大 |
| ADR-07 | 原始附件不可变，缓存可重建 | 备份、引用与 GC 可控 | 修改附件生成新对象，不原地覆写 |
| ADR-08 | 全文历史 + 分层摘要/记忆 | 控制 token 和保留可追溯历史 | embedding 可选，不默认外传全部历史 |
| ADR-09 | UI 事件可重放/重查询，不依赖一次性广播 | 隐藏/断线/多窗口可恢复 | 不为首版引入外部 broker |
| ADR-10 | 本地管理身份与群主身份分开 | 用户已明确群主只四项权限 | 群参数字段白名单等待确认 |

以上除群主四项权限和平等聊天语义外，均为推荐而非用户已批准的决定。

## 4. 模块责任与 I/O

| 模块 | 输入 | 输出 | 不负责 |
|---|---|---|---|
| `app_lifecycle` | 启动、关闭、托盘、OS 睡眠/唤醒、退出 | 生命周期状态、取消信号、维护锁 | 成员是否愿意聊天 |
| `ipc_gateway` | 有窗口来源的 command DTO | 校验后的用例调用、typed error | 任意路径或 SQL 透传 |
| `chat_service` | 用户消息/合法候选动作、撤回、引用 | 已提交 Message、事件、检索结果 | 模型调用或人物风格 |
| `group_service` | 操作者、群版本、白名单 patch/通告/@all | 群资料版本、通告消息、审计元数据 | 控场、改成员权限或预算 |
| `agent_config` | 预设选择、文件候选、有效版本 | 配置快照、SKILL、差异和验证结果 | 读取密钥正文到前端 |
| `agent_supervisor` | 已提交事件、启停、有效配置 | actor 生命周期、合并观察机会、状态 | 统一决定谁该发言 |
| `agent_actor` | 自己的观察机会、上下文、配置 | DecisionEnvelope、唤醒计划、候选动作 | 绕过宿主执行工具 |
| `scheduler` | 模型提出的合法时间计划、硬保护暂停 | 到期机会、取消/恢复 | 随机生成社交时间或话题 |
| `context_assembler` | 成员、目标游标、token 预算、引用 | 有边界的 ContextBundle、用量估算 | 自主发布摘要为群消息 |
| `memory_service` | 原始范围、压缩任务、召回条件、失效事件 | 群摘要、成员记忆、来源和检索结果 | 把推测当事实、删除原聊天 |
| `model_gateway` | 标准 ModelRequest、能力要求、cancel token | 标准 completion/decision、usage、错误 | 角色社交权或消息持久化 |
| `tool_runner` | 已授权 ToolJob、预算、cancel | 任务状态、结构化结果/附件 | 默认执行任意代码/网页命令 |
| `budget_service` | 请求预估、实际 usage、币种和配额 | 预留、结算、允许/拒绝原因 | 声称估算等于账单 |
| `authorization` | 本地用户授权、actor/tool/endpoint | 权限判定、一次性批准票据 | 接受模型自授权 |
| `storage` | repository command/query | 事务结果、已提交事件游标 | 业务拟人化判断 |
| `attachment_service` | 受限来源句柄/授权 URL、内容限制 | object ID、元数据、缩略图、GC | 访问模型生成任意路径 |
| `data_transfer` | 备份/迁移/恢复请求、维护状态 | manifest、阶段日志、恢复结果 | 先删原库或静默合并 |
| `notification` | 已提交新消息、阅读游标、偏好 | 未读、托盘状态、聚合通知 | 给系统勿扰提供绕过弹窗 |

依赖方向：前端 → IPC → 用例 → 领域接口 → 基础设施。Provider、SQLite、Tauri 平台实现是边缘适配层，不能反向把协议类型泄漏到 UI。

## 5. 线程、任务和队列

### 5.1 线程/运行空间

- Tauri UI 线程只处理原生窗口/托盘等需要主线程的动作。
- Tokio runtime 负责网络和 actor；不在 async task 中直接做长时间同步 SQLite 或图像解码。
- 专用数据库线程执行串行写与可控查询；读取可使用少量独立连接/受限工作线程，但 driver 统一。
- 图片解码、哈希、大文件压缩放受限 blocking pool；同时处理数量受预算约束。
- 主窗口与设置窗口共享同一 Rust 应用状态，不复制调度器。

### 5.2 队列语义

| 队列 | 是否有界 | 过载行为 |
|---|---|---|
| actor 观察信箱 | 有界，但事件范围可合并 | 合并成游标范围，不丢“有新消息”的事实，不无限保存每个 prompt |
| 模型请求 | 全局/提供方有界 | 等待或拒绝，显示限额；不无限起任务 |
| 群消息发布 | 串行短事务 | 校验幂等/权限/有效性，事务后广播 |
| 工具任务 | 有界、持久化 | 排队/待授权，不让工具任务饿死用户操作 |
| DB 写 | 有界 | 返回 backpressure 或短等待，不把未提交消息标成成功 |
| UI 事件 | 增量带游标 | 发现缺口重新取快照和事件，不盲信收到所有广播 |
| 备份/迁移 | 单维护操作 | 同类互斥，显示进行中，避免竞争切换数据根 |

技术合并窗口是减少重复请求的机制，不是代码决定成员该不该发言。具体默认值统一在 [00](00-文档导航与确认清单.md)。

## 6. 生命周期与恢复

### 6.1 启动顺序

1. 获得应用单实例锁及数据根写入锁。
2. 从固定用户应用目录读取 bootstrap 和维护恢复日志。
3. 若有未完成迁移/恢复，按阶段检查目标和旧根；不先启动成员。
4. 打开 SQLite，启用连接约束，检查 schema 并执行安全升级。
5. 读取已激活配置快照，验证外部文件候选差异；未验证文件不能运行。
6. 初始化凭据状态、提供方能力、预算和工具授权。
7. 建立 outbox/event cursor、通知未读和 actor 注册表。
8. 按用户运行偏好启用成员，处理有效未过期计划；不集中补跑睡眠期间的每个时钟 tick。
9. 创建/显示主窗口和托盘，提供状态快照。

缺密钥只让对应成员进入 NeedsConfiguration；库损坏、根路径无效或维护日志不完整则进入数据恢复模式，不静默新建空库。

### 6.2 隐藏、暂停、锁屏、睡眠

- 隐藏到托盘：WebView 可被节流，但 Rust 的已授权运行继续。
- 全部暂停：不接受新的自动决策，取消尚未发出的社交动作与可取消网络；持久数据不删。
- 单成员暂停：只影响该 actor 及其社交动作；工具任务是否暂停/取消按任务界面明确选择。
- 锁屏/勿扰：通知策略与后台运行开关分开。建议静默时抑制主动话题，具体默认需确认。
- OS 睡眠：任务不保证运行；恢复时合并事件、重新判断过期草稿，不能补发所有计划。
- 用户输入本地仍可工作，不要求模型服务在线。

### 6.3 显式退出

1. 设置 `ShuttingDown`，拒绝新调用和新自动发言。
2. 取消社交 actor 与待发条目，停止到期计划。
3. 标记尚未完成的远端任务，保存 job ID、预算预留和结果未知边界。
4. 允许当前短数据库事务完成，flush 配置/维护日志。
5. 释放连接、附件/托盘句柄；有界等待后退出。

不能承诺远端请求因此不计费。正在迁移/恢复时普通关闭隐藏，退出需用户确认并进入可恢复中断流程。

## 7. 核心数据约定

- 实体 ID：不透明字符串，推荐 UUIDv7；前端不得从 ID 推导权限或路径。
- `message_seq`：SQLite 分配的稳定单调消息序号，用于排序和历史分页。
- `event_seq`：持久领域事件游标，与 message_seq 不同；撤回/群修改也有事件。
- `config_revision`：已激活的不可变配置版本。
- `room_version`：群资料的乐观锁版本；只在群资料修改时变化。
- `content_epoch`：撤回、删除或其他使既有上下文失效的内容版本。
- 时间：数据库 UTC epoch milliseconds，UI 用用户时区展示；调度同时使用运行期单调时钟。
- 相对路径：附件/配置路径必须位于当前数据根内，不从模型输出接受任意本机路径。
- 媒体状态：available/expired/missing/quarantined，不能用缺少正文代替类型。
- 不同请求 ID、decision ID、action ID、task ID 不混用。

完整实体和约束见 [05](05-数据存储与迁移备份设计.md)。

## 8. 前后端 command 合同

这里只定义领域合同，实际 Rust/TypeScript DTO 在批准后生成并实施。所有自定义 command 同样要限制窗口来源及业务授权，不能认为 Tauri 插件 capability 已自动限制所有自定义命令。

通用入参：`client_request_id`（写操作幂等）、`expected_revision`（需要乐观锁时）、具体 payload。操作者来自可信 IPC 来源/会话，普通前端不能通过传 `actor_id` 冒充任意成员。

| Command | 输入要点 | 输出要点 |
|---|---|---|
| `app_get_snapshot` | 可选 last_event_seq | 生命周期、群资料、成员、未读、运行状态；不含密钥 |
| `chat_send` | parts、结构化 mentions、quote_id、request_id | 已提交 message ID/seq；失败不清草稿 |
| `chat_list` | before_seq/after_seq/around_seq 中一项、limit | 有序页面、两端游标、是否更多 |
| `chat_search` | query、日期/成员筛选、cursor、limit | 结果 ID/seq/片段、搜索语义、取消句柄 |
| `chat_recall` | message_id、request_id | tombstone 和新 content_epoch 或具体错误 |
| `chat_mark_read` | visible_through_seq、focus 状态 | 新阅读游标与未读 |
| `user_profile_get/save` | 本地身份资料、expected_revision、头像对象 ID | 公开资料新版本；当前本地用户身份由宿主绑定，过去消息不改 |
| `agent_retry_online` | agent ID、当前配置 revision、测试项与付费知情 | 测试/上线状态、脱敏错误及可能费用；不自动换模型 |
| `group_update` | expected room_version、白名单 patch | 群资料新版本和 audit ID |
| `group_publish_announcement` | title、parts、显式 mention_all | 通告消息 ID、权限判定 |
| `group_set_owner` | participant ID、expected room_version | 新群主；仅本地应用管理身份可调用 |
| `agent_list/get` | agent ID | 已激活配置的脱敏 DTO、状态 |
| `agent_save` | 配置候选、SKILL、expected_revision | 已激活 revision 或字段错误/冲突 |
| `agent_set_enabled` | agent ID、enabled、request_id | 状态和取消结果 |
| `agent_delete` | agent ID、保留历史/清记忆选项 | tombstone/清理计划 |
| `profile_save` | 非敏感配置、expected_revision | 新模板版本、影响和副本关系 |
| `secret_set/delete/status` | credential ref、必要凭据输入 | 是否设置、绑定的 endpoint；永不读回明文 |
| `profile_test` | profile ID、测试项、付费知情确认 | 能力/认证/usage/错误；不用真实聊天测试 |
| `runtime_pause/resume` | 范围、原因 | 运行状态和限制，不修改 SKILL |
| `task_list/get/cancel` | task ID/筛选 | 状态、可取消边界、结果摘要 |
| `task_approve` | task ID、请求摘要哈希、允许一次/拒绝 | 绑定操作的批准票据；参数变化需重审 |
| `attachment_import` | OS 选择/粘贴得到的受限句柄 | staging handle、元数据、检查结果 |
| `attachment_open/save_as` | object ID、显式用户动作 | 授权访问/另存结果，不接受裸路径跳转 |
| `data_backup/migrate/restore` | 授权目的地句柄、选项、request_id | operation ID，事件报告阶段 |
| `data_export` | 范围、格式、媒体选项 | export operation，不声称可完整恢复 |
| `memory_list/update/delete` | 范围、条目 ID、expected_revision | 来源与新版本/失效记录 |
| `diagnostics_export` | 明确脱敏范围 | 本地文件结果，不自动上传 |

建议分页参数以 [00](00-文档导航与确认清单.md) 的 P-DATA-01 为准。Chat list 不使用 offset 全量翻页。

### 8.1 通用 wire 规则

- 当前合同 schema_version 为 `0.2`；JSON 字段统一 snake_case。
- 实体 ID 为不透明字符串；message_seq/event_seq/config_revision/room_version/content_epoch 等可能超 JS 安全整数的大整数以十进制字符串传输，比较/排序由明确解析或后端完成，不能字符串字典序排序。
- 时间 UTC epoch milliseconds 为安全整数；延迟/limit/ordinal 使用有范围的整数，null 与空数组语义明确。
- Command 成功输出为 `{schema_version, data}`；失败为 `{schema_version, error}`，error 使用第 11 节结构，不夹带 provider raw body。
- 写操作 client_request_id 去重；expected_revision/expected_room_version 根据操作绑定，冲突返回错误不静默覆盖。
- `chat_send.parts` 与 04 的消息 parts 使用同一判别联合，quote_message_id、mention_ids、mention_all 明确；UI 输入得到的 emote/附件对象需后端解析验证。
- 分页 before_seq/after_seq/around_seq 互斥，返回 items、first_seq/last_seq、has_more_before/after 及快照高水位；越界/缺目标不是假空成功。
- 未知字段/枚举拒绝，不把自由 JSON 透传给 SQL/provider。实际 DTO/schema 在编码阶段由同一合同来源生成并双端验证。

### 8.2 原子内部 API 与未来外部调用

ChatService 的 send/list/search/recall、Context 的 build/summary_prepare、Memory 的 query/commit、ModelGateway 的 request_decision、ToolRunner 的 create/query/cancel 均为原子用例边界；生成回复与总结记录不必须依赖点击 UI。

当前仅用于本地应用与内部受控工具，不创建外部 MCP server、不监听本地控制端口，也不让模型以 command 字符串直接调用。未来外部化须添加独立认证、scope、费用批准和审计；模型生成候选回复与真正发布消息仍是两步，不把“生成”接口默认设计成自动发送。

## 9. 事件、outbox 与窗口恢复

事件 envelope：`schema_version`、`event_seq`、`event_id`、`occurred_at`、`kind`、`entity_id`、`entity_revision`、payload（脱敏）。seq/版本按第 8.1 节序列化为十进制字符串。事件写入与消息/状态变更同一事务；事务提交后 Rust 发布到 actor 和 UI，应用 status_notice 走独立事件、不默认触发全体模型。

| Event | 关键 payload | 消费者 |
|---|---|---|
| `MessageCommitted` | message ID/seq、sender ID、mentions、content_epoch | UI、actors、通知、记忆任务 |
| `MessageRecalled/Deleted` | ID、content_epoch、受影响来源范围 | UI、候选取消、FTS/记忆失效、通知 |
| `GroupUpdated` | room_version、变化字段、操作者 | UI、有效上下文信息 |
| `AnnouncementCommitted` | 通告消息 ID、显式提及集合 | UI、actors、通知；不是 system 指令 |
| `AgentConfigActivated` | agent ID、revision、差异类别 | supervisor、UI |
| `AgentStateChanged` | 有限枚举、原因码、唤醒时间可选 | UI、诊断 |
| `ParticipantProfileChanged` | participant ID、资料 revision、受限变化字段 | UI、环境快照；不重写历史昵称/头像 |
| `StatusNoticeCommitted` | 小标记消息 ID、成员 ID、offline_episode_id、公开昵称快照 | UI、通知；不是全体模型发言触发 |
| `TaskStateChanged` | task ID、state、结果引用/错误 | UI、任务恢复 |
| `UsageSettled` | request ID、usage/未知项、预算余额 | 预算 UI，不触发全群发言 |
| `ProtectionTriggered` | 类别、作用域、恢复条件 | UI、supervisor |
| `DataOperationProgress` | operation ID、阶段、完成/错误 | UI、恢复流程 |

避免把日志和每个内部工具进度都变成群消息事件，以免反复唤醒成员。

UI 重连：先订阅/取得稳定高水位，再取状态快照与该高水位后的事件，去重 event ID；若事件保留窗口不足则重新快照。窗口隐藏不会改变 actor 的持久观察游标。领域 outbox 不是永久第二份聊天正文，不重复保留撤回原文。

## 10. 内部调用合同

### 10.1 `DecisionEnvelope`

必备宿主字段：`schema_version`、`decision_id/agent_id`、`config_revision`、`observed_through_seq`、`content_epoch`、`room_version`、`authorization_revision`、`request_id`、`conversation_chain_id`，以及验证后的 `decision` 对象。模型不能自设身份或可信游标。

`decision` 的唯一字段定义在 04 第 6 节：participation、messages、recalls、tool_requests、group_patch、announcement、profile_patch、wake_plan、topic_hint、extra_data。participation 为 speak/observe/defer/sleep；附加数据是受控 annotations/记忆候选，不是私有思维链。

执行器内部 `actions` 由宿主按 04 的固定顺序规范化，生成 action ID/ordinal 和依赖；不是另一套模型输出字段。群主权限、自己消息撤回、同伴委托和自己资料修改逐项验证，实际工具调用的 purpose/schema 见 07。

具体约束与 JSON 示例见 [04](04-智能体运行与拟人化设计.md)。

### 10.2 `ModelRequest/Response`

输入：profile snapshot、capability requirements、system/SKILL、按角色映射的 messages、response schema、reasoning intent、输入输出预算、网络策略、取消信号。

输出：标准 content/decision、tool requests（仅声明）、usage（含来源/未知项）、finish reason、provider request ID、必要的不可见协议会话状态。不能让 provider adapter 自动发布群消息。

### 10.3 `ToolJob/Result`

输入：task ID、actor、明确委托来源、工具类型、已验证参数、授权票据、origin depth、预算、幂等能力、cancel policy。

输出：状态、文本/来源/附件对象引用、错误类别、计费/取消不确定性。每个 job 有独立恢复状态，不靠聊天气泡判断是否完成。

### 10.4 `ContextBundle`

包含：身份及安全规则、成员 SKILL、有限群资料、近期有效消息、引用目标、相关摘要/记忆、授权工具信息、图片输入和预算报告；带来源 ID/seq、content_epoch 和 token 估算等级。

不包含：API Key、任意本地路径、旧撤回正文、其他成员未经授权的私人记忆或原始网页中的命令权限。

## 11. 错误合同

所有错误包含 `code`、可读 message、retryability、可选字段路径、trace_id 和是否可能已收费。只显示必要信息，不回传鉴权 header、完整 provider body 或密钥。

| 类别 | 例子 | 处理 |
|---|---|---|
| 输入/权限 | INVALID_INPUT、PERMISSION_DENIED、OWNER_CHANGED | 不重试，提示修正/刷新 |
| 版本 | CONFIG_CONFLICT、CONTEXT_STALE | 重取/重新判断，不覆盖新版本 |
| 撤回 | RECALL_WINDOW_EXPIRED、NOT_MESSAGE_OWNER | 明确业务反馈 |
| 配置/能力 | SECRET_MISSING、CAPABILITY_UNSUPPORTED | 进入待配置，不无限模型重试 |
| 运行/费用 | PAUSED、BUDGET_EXCEEDED、BACKPRESSURE | 显示保护，用户控制恢复 |
| Provider | AUTH_FAILED、RATE_LIMITED、TIMEOUT、INVALID_OUTPUT | 有限重试按提供方政策，不在群里刷屏 |
| 数据 | DISK_FULL、DB_BUSY、DB_CORRUPT、IMPORT_INVALID | 保留原数据，进入恢复或取消 |
| 工具不确定 | RESULT_UNKNOWN、CANCEL_NOT_CONFIRMED | 不自动重提交付费非幂等操作 |

## 13. 各模块完成定义

- 有输入、输出、错误、取消、并发与持久化责任的合同测试。
- 有真实实现，不只有空 interface、假数据和 TODO。
- 与上一层的集成场景验证，特别是跨事务/异步边界。
- 文档中的关键参数、平台限制与实际实现保持一致。
- Provider 关键能力用实际 endpoint 合同测试，UI 用桌面功能测试，不把单元测试当全部验收。
- 架构需要改变时更新 ADR 和确认清单，再改变有影响的模块，不能绕过用户尚未确认的决策。
