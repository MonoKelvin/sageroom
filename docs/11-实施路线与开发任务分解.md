# Sageroom 实施路线与开发任务分解

> 版本：0.6｜状态：聊天/成员/模型/经历/托盘/设置/数据目录迁移与拟人化门控已实现并提交推送至 0.2.2，完整 P1 尚未完成｜日期：2026-11-26\
> 开发、提交与推送已按用户逐次明确授权执行，最近一次为 2026-11-25 的 0.2.2 推送。测试使用隔离数据与本地模型，不导入 `.env`。付费服务、外传与发布仍需明确授权。需求基线见 [02](02-用户需求与产品规格.md)，参数见 [00](00-文档导航与确认清单.md)，测试见 [10](10-测试验收与性能评估.md)。

## 1. 阶段与执行原则

采用“先验证关键不可逆假设，再做真实最小闭环，之后补齐完整桌面需求”的分期。不是先做大量空 UI、interface 和假 agent，再宣布完成。

- 文档完成、技术资料核实、代码实现、测试通过、实机验收是不同状态。
- P0 是第一阶段闭环，P1 是完整初始需求，P2 才是可选增强。
- 先确定领域/IPC/模型 JSON 的版本和 I/O，再按模块实现；改变边界需同步相关合同。
- 每模块必须有真实成功、失败、取消和恢复路径，不留无法接入的半成品。
- 先复用成熟库，只在确定协议差异处增加窄 adapter，不引入多套数据库或动画系统。
- 智能体语义由模型判断；代码实现安全、预算、调度和一致性，不能用随机回话填补缺失能力。
- 编码和仓库操作另经授权；获批后遵循用户 main 分支及会话关联提交约定，不自行开测试分支。

## 3. 工作包规范

每工作包记录输入合同、输出/产物、依赖、实现位置、测试 IDs、错误/取消/恢复责任、状态和证据。首批骨架与源码已经创建，实际子场景状态见第 11 节；其余位置仍按获批工作包确定。

状态：Planned → Ready → InProgress → Implemented → Verified → Accepted。Blocked 写明门槛；Implemented 不等于 Accepted。首批已有真实实现和已验证子场景，但不将子集提升为整个工作包或完整 V1 Accepted；实际范围见第 11 节。

“完成”至少包括：真实实现可被上一层调用、测试和实机要求通过、关键错误路径可演示、无密钥/未授权外传、相关文档随真实合同更新。
