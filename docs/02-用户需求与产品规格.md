# Sageroom 用户需求与产品规格

> 文档版本：0.3｜状态：待用户评审的设计草案｜日期：2026-11-18\
> 输入：[初始需求](初始需求.md)。本文展开需求，不代表新增建议已经获得批准。技术方案见 [01](01-技术调研与选型评估.md)，设计总览和待确认项见 [00](00-文档导航与确认清单.md)。

## 1. 产品定位

Sageroom 是一个本地优先的桌面 AI 群聊应用：用户与多个具备独立性格、模型和记忆的智能体，共同生活在一个聊天室中。一般智能体是群成员，不是默认服从用户的客服；工具型智能体才在明确任务中承担执行者角色。

产品的核心体验不是“同时显示多个模型回答”，而是：

- 有人接话，有人沉默，有人晚点回来；智能体之间也能形成自然的对话。
- 用户可以参与，也可以暂时不参与，不要求每句话都围绕用户展开。
- 没有值得聊的内容时，聊天室安静下来，不靠随机脚本制造热闹。
- 特定成员可以在被明确委托后，异步查询资料、生成图片、计算或给出代码。
- 成员、聊天记录和本地资源受用户控制；外部模型调用及其费用可见、可暂停。

“本地优先”不等于“完全离线”：界面、聊天存储和调度本地运行，使用远程模型、搜索和生图服务时，相应内容会离开设备。

## 2. 需求解释规则

### 2.1 来源与优先级

1. 原始需求中的明确要求是产品基线。
2. 本文中的补充约束用于把要求落地为可验证行为。
3. 标记“建议”“待确认”的内容只能作为草案默认值，不能直接当作用户决定。
4. 技术安全限制可以阻止危险执行，但不能偷偷替代“智能体自己决定是否聊天”的要求。
5. 所有版本范围和默认数值最终以 [00 的确认清单](00-文档导航与确认清单.md) 为准。

优先级含义：

| 标记 | 含义 |
|---|---|
| P0 | 最先完成的闭环及不可省略的安全、数据一致性基础 |
| P1 | 初始需求完整桌面版仍需要实现，只是在后续增量交付 |
| P2 | 可选增强，不属于未经确认就必须增加的范围 |

P0 演示版不等于完整 V1；不能以“做完 MVP”为由宣布初始需求全部完成。

### 2.2 原文中需要澄清的表达

| 原始表达 | 可执行的解释 | 不应作出的承诺 |
|---|---|---|
| “不占内存” | 相比嵌入完整浏览器的方案控制常驻资源，并设实际测量预算 | 不可能承诺零内存、所有机器相同占用 |
| “独立实时运行的线程” | 每个智能体拥有独立配置、状态、事件订阅和异步任务；建议以独立 actor 落地，而非每成员一个 OS 线程/进程 | 不默认每个成员都启动一份浏览器或 Node 进程 |
| “监控所有历史消息” | 所有已提交消息均可被运行时感知，历史可检索；单次请求只取预算内上下文 | 不把整个数据库永久输入每次模型请求 |
| “不能通过代码判断是否回复” | 内容、接话、忽略、休息、主动话题和拟人化行为由各智能体模型决定 | 不排除限额、权限、撤回时限等必须由代码强制的保护 |
| “极低概率撤回、错别字” | 用 SKILL 指导罕见且有语境的行为，模型提出动作，回归测试测量实际频率 | 不使用随机数注入错误，不保证精确概率 |
| “去除思考参数” | 支持时明确关闭 thinking/reasoning；不支持关闭时提示能力限制 | 不能用“隐藏思考文本”冒充停止产生或计费 reasoning tokens |
| “自动推送热点” | 有已授权的新闻/搜索来源且资料时间可核实时，成员决定是否发起话题 | 不能把模型训练知识当作实时新闻 |
| “群主可以是智能体” | 用户已明确：只增加修改群名称、修改群参数、@所有人、发通告四项群管理权限；聊天地位与普通成员相同 | 不拥有控场、强制回复、话题优先权，也不默认获得密钥、财务或本地系统权限 |

## 3. 用户、角色与权限

### 3.1 主要用户

- 希望拥有一个轻量、常驻、可随时打开的 AI 聊天群的桌面用户。
- 愿意自行配置模型服务，关注性格差异、自然对话和成本的人。
- 需要偶尔召唤工具成员，但不希望整个界面变成任务工作台的人。

### 3.2 产品内角色

| 角色 | 能力 | 明确不具备的能力 |
|---|---|---|
| 本地用户 | 发消息、管理成员与模型、管理数据、控制运行、授权工具 | 不因自己是用户就要求所有社交成员每句必答 |
| 社交智能体 | 观察群聊、决定发言/沉默/休息、引用、提及、使用已授权媒体能力 | 修改自身权限、读取密钥、访问任意本地路径、绕过预算 |
| 工具智能体 | 接收明确任务、反馈状态与结果、按授权使用工具 | 无需求时频繁发言；把普通网页指令当作操作授权 |
| 群主 | 修改群名称、修改群参数、@所有人、发通告；普通聊天与其他成员一样 | 控场、强制回复、话题优先权；自动获得应用管理、删除记录或无限花费权限 |
| 应用运行时 | 持久化、执行合法动作、调度、限流、校验 | 用随机发言逻辑替代智能体语义决策 |

当前版本只存在一个本地真人身份和一个聊天室，不提供互联网多人联机、账号体系或远程协同。这直接来自原始需求，不是新增范围建议。

## 4. 版本范围

### 4.1 P0 闭环

- 桌面单聊天室、用户文本聊天和历史加载。
- 内置 Sage，配置一个实际模型后可用；未配置时仍能打开和管理应用。
- 多成员独立 SKILL、模型设置副本、用户提及和引用。
- 每个智能体用模型决定回复、忽略、等待或休息。
- 智能体之间可连续接话，但受可解释的安全配额限制。
- 独立后台运行、关闭隐藏到托盘、全部暂停和明确退出。
- SQLite 持久化、基本中文检索、密钥隔离、调用记录和请求级取消。
- 安全备份恢复基础必须先于大规模真实聊天使用。

### 4.2 P1 完整桌面版

- 模型决定主动话题、分条发送、稀少撤回和语境相关的拟人行为。
- 图片、文件、emoji、颜文字、自定义表情及 GIF。
- 工具智能体的搜索、生图、计算及代码文本生成。
- 视觉理解、上下文压缩、独立记忆检索及管理。
- 托盘未读、可用平台的系统通知、声音、预览和勿扰。
- 存储迁移、附件清理、一键备份、验证后导入、可读导出。
- 完整设置、成员组装、提示词预览、成本预算与故障恢复。
- 无障碍、主题、动画降级、安装分发、真实桌面端验收。

### 4.3 不默认进入 V1 的内容

以下不是删除原始需求，而是尚未被要求或需要额外授权的增强：

- 移动端适配、手机后台长驻智能体，归入下一大版本研究。
- 多聊天室、多人联网、账号登录、云同步、服务端托管。
- 任意代码在用户机器执行、任意 shell、浏览器自动控制、自动安装插件。
- 开机自动启动；常驻托盘不等于安装后自动开机运行。
- 自动读取整个硬盘、通讯录、邮件或私人网页。
- 离线本地大模型管理和模型下载器。
- 语音通话、视频通话、语音克隆。
- 自动联网下载和执行第三方 SKILL/MCP 程序。
- 向量数据库独立服务、复杂多级自治组织。

简短代码“生成”属于 P1；代码“执行”不是同一能力，不混淆。

| ID | 优先级 | 规格及验收条件 |

| FR-CHAT-012 | P0 | 用户输入中文时正确处理 IME；组合输入中的 Enter 不发送，Shift+Enter 换行 |
| FR-CHAT-013 | P1 | 用户可清理指定范围记录，预览影响并确认；已导出和第三方模型内容不能承诺追回 |

消息“已发送”表示已进入本地聊天室，不代表任何智能体一定看到、理解或回复；工具任务的“完成”有单独状态。

### 6.3.1 群主的四项群管理权限（用户已明确）

| ID | 优先级 | 规格及验收条件 |
|---|---|---|
| FR-GROUP-001 | P1 | 只有当前群主能以群内身份修改群名称；修改有版本、操作者和可查看记录 |
| FR-GROUP-002 | P1 | 只有当前群主能修改获准的群参数字段；具体字段白名单待确认，不包含模型、密钥、工具授权、文件路径及安全预算 |
| FR-GROUP-003 | P1 | 当前群主可发送结构化 @所有人；接收成员按发送时成员集合确定，普通成员不能通过输入相同文本获取该权限 |
| FR-GROUP-004 | P1 | 当前群主可发通告，以群内消息和通告视图呈现；通告不是 system 指令，不强制其他成员回应或服从 |

## 7. 关键用户旅程

### UC-01：首次启动并启用 Sage

- 前置：应用安装成功，无任何凭据。
- 用户打开应用，看到聊天室外壳、Sage 的未配置状态和“配置模型”入口。
- 新建提供方，填写凭据、模型及地址，查看哪些能力可用。
- 用户知晓连接测试可能产生费用，主动点击测试。
- 保存模型后，选择给 Sage 使用的参数副本，确认运行和外部传输提示。
- 成员可以根据初始化机会选择问候，也可以不发言；不硬编码欢迎消息假冒模型输出。
- 失败分支：密钥错误、地址无效、不支持 non-thinking、网络超时均可修正，应用仍可使用。

### UC-02：普通群聊并自然安静

- 用户发“今天工作真是累”。
- 各活跃成员观察；有的接话，有的观察，有的表示稍后回来。
- 后续成员消息可以引起同伴回应；不是每次按固定顺序轮流回答。
- 若模型均决定不接话，UI 无错误提示，聊天室进入安静状态。
- 若硬配额阻止，运行状态显示“自动聊天已达到限额”，不能伪装成所有成员自主休息。

### UC-03：用户暂时离开，智能体互聊

- 主窗口隐藏到托盘，运行未暂停。
- 智能体执行已安排的合法唤醒，决定有没有值得聊的新内容。
- 用户并未在线不意味着自动获得联网和生图授权。
- 未读记录增长，通知按设置聚合；再次打开保留未读分界。
- 用户彻底退出应用后无本地任务继续运行，不暗示 OS 会代为唤醒已退出进程。

### UC-04：组装新成员并独立修改

- 用户从模型、性格及工具预设创建成员，查看生效内容。
- 修改幽默/直接程度及模型温度，保存为该成员副本。
- 再修改全局预设，既有成员参数不改变；UI 可提示有新预设版本但必须主动采用。
- 共用凭据更新影响使用该凭据的服务，UI 明确显示共享关系，不将此误描述为完全隔离。

### UC-05：引用和提及

- 用户引用较早消息并选择同名成员中的某一个。
- 请求里保留引用来源和具体成员 ID；提及在 UI 可点击。
- 原消息已撤回时只提供占位，不把旧快照再次传给模型。
- 社交成员可以选择不回复；工具成员需要明确任务再进入任务流程。

### UC-06：发图片、选择表情

- 用户粘贴截图，先看到本地预览和大小；取消不会留下持久发送消息。
- 上传授权开启时，具备视觉能力的必要请求才能读取图片。
- 非视觉成员看到“图片（未提供视觉内容）”，不得假称看到了图片。
- 把 GIF 收藏为表情后，原聊天附件到期不应删除仍被收藏引用的文件。

### UC-07：召唤工具成员生图

- 用户或普通成员发送结构化提及和明确生图需求。
- 工具检查授权、模型、预算与任务深度；需要确认时进入待授权。
- 后台运行，主聊天室保持可聊天；群内只显示少量必要反馈。
- 成功后落地图片并发出结果消息；失败给出重试选择。
- 若请求已到远端但响应丢失，显示“结果未知，可能已计费”，不自动再次发起。

### UC-08：热点查询

- 工具检索并记录来源时间，网页内容不能改变工具权限。
- 返回摘要和可点击来源；没有真实检索结果时不编造链接或新闻。
- 社交成员可对结果发表评论，也可不回应；来源引用不等于准确性保证。

### UC-09：撤回

- 用户在消息发布 119 秒时撤回，原文从当前群聊视图和后续上下文移除。
- 发布满 120 秒时请求返回明确的时限错误。
- 已有引用变为“原消息已撤回”，已生成的受影响记忆被标记失效。
- 必要时取消基于旧消息生成的待发草稿；不能追回已经在远端处理中的输入。

### UC-10：迁移及备份恢复

- 用户预览空间、目标路径和受影响运行任务。
- 应用进入数据维护状态，生成一致快照，验证后切换。
- 目标准备失败不影响旧库；切换成功仍保留恢复入口。
- 在新设备恢复备份时，聊天和成员恢复，密钥不默认携带，成员先停用等待凭据重新绑定。

## 8. 业务规则

| 编号 | 规则 |
|---|---|
| BR-01 | 全局只存在一个聊天室；模型和工具请求属于该聊天室与具体发起成员 |
| BR-02 | 人工应用管理权限与群主身份分离；群主仅增加群名、群参数、@所有人、通告四项权限，普通聊天地位平等 |
| BR-03 | 一个成员同时最多一个有效社交决策；新事件合并而不是无限排队 |
| BR-04 | 消息、配置及权限版本改变时，待发动作必须进行有效性检查 |
| BR-05 | 120 秒撤回按应用可信时间基准执行，不接受模型给出的发布时间 |
| BR-06 | 所有聊天动作有来源、动作 ID 和幂等键；重试不能重复发布。同伴委托按已提交消息/目标去重，自身工具不再走第二条委托入口 |
| BR-07 | 工具授权只由本地用户赋予，智能体互相提及不扩大授权 |
| BR-08 | 模型输出和网页都视为外部输入；通过结构和权限验证才可执行 |
| BR-09 | 配置副本不含密钥，凭据引用共享这一事实必须可见 |
| BR-10 | 默认长期保留文本，附件与缓存采用不同策略；用户原件不被清理 |
| BR-11 | 备份与可读导出不同；恢复验证格式/引用、刷新运行世代，保留同安装已用额度与未知费用，不回滚财务保护 |
| BR-12 | 已撤回或删除的内容不得通过引用、FTS、旧摘要或记忆重新进入未来上下文 |
| BR-13 | 未知计费不能按免费处理；预算估算与服务商最终账单分别显示 |
| BR-14 | 应用故障、限额、休眠和模型主动沉默是四种不同状态 |
| BR-15 | 默认工具代码只生成文本，不执行；文件与 URL 不自动打开或运行 |

## 9. 非功能需求

| ID | 指标类别 | 可验证要求 |
|---|---|---|
| NFR-01 | 资源 | 按主进程与 WebView2 相关进程合计测量；初始性能目标和参考设备见 [10](10-测试验收与性能评估.md)，未经实测不是承诺 |
| NFR-02 | 输入 | 本地发送/输入响应不能依赖模型网络返回；网络慢时仍可滚动、编辑和暂停 |
| NFR-03 | 大历史 | 基准 10 万条文本消息下分页和搜索可用，不一次载入全部记录 |
| NFR-04 | 一致性 | 消息仅在事务提交后发布事件；配置保存和迁移发生崩溃可恢复 |
| NFR-05 | 可控成本 | 调用记录包括成功、沉默、重试、取消、压缩和工具；不能只统计“发了消息”的调用 |
| NFR-06 | 安全 | 凭据不进入前端、提示词、普通日志或默认备份；IPC 不能访问任意路径 |
| NFR-07 | 隐私 | 无隐含遥测；用户可控制发给哪些提供方的文本、图片和记忆 |
| NFR-08 | 无障碍 | 键盘完成主要流程；文本对比度、减少动画、可读名称和焦点管理纳入验收 |
| NFR-09 | 可测试 | Provider、工具、时钟、事件和存储模块有清晰可替换合同，可离线复现调度场景 |
| NFR-10 | 可维护 | 模块按输入输出隔离；修改模型提供方不要求修改聊天列表或数据库基础逻辑 |
| NFR-11 | 兼容 | 仅承诺实际覆盖的 OS/安装态/权限组合，未测试的平台标记未支持 |
| NFR-12 | 恢复 | 暂停/崩溃/断电/目录迁移/数据库升级均有明确恢复路径，不以删除数据解决问题 |

## 10. 费用与联网知情

首次启用智能体前，至少说明：

- 即使成员选择不回复，也可能已经调用模型并付费。
- 一条群消息会引起多个活跃成员决策，成员之间的消息也可能放大请求量。
- 主动唤醒、摘要压缩、记忆提取、搜索和生图有独立开销。
- 图片输入可能大幅增加 token 或产生额外请求；reasoning tokens 可能计费。
- “取消本地任务”不等于“远端取消执行/取消收费”。
- 配置价格可能过期，最终费用以服务商账单为准。

提供方凭据未配置、余额不足、全局预算耗尽时，应用本地功能继续可用。不得自动换用其他付费提供方，以免扩大隐私和费用范围。

## 11. 验收基线

完成 V1 必须同时满足：

1. 所有 UR-01～UR-22 都有实现、测试及明确的平台边界。
2. 所有 P0、P1 功能达到可演示闭环，而非仅有类型定义或空 UI。
3. 不用随机发言、固定轮询必答或假响应替代自主模型决策。
4. 测试证明暂停、风暴保护、撤回、目录迁移、备份恢复和凭据隔离有效。
5. 桌面实机验证托盘、通知、毛玻璃降级、输入法和后台生命期。
6. 有可复现的模型合同测试和拟人化评测结果，承认非确定性而不是承诺绝对自然。
7. 用户完成关键决策确认，设计文档由草案更新为批准基线。

## 12. 用户评审时重点确认

- V1 是否先仅支持 Windows，以及需要测试的 Windows 版本。
- “独立实时线程”以独立异步 actor 实现是否满足需求；需要更强 OS 线程/进程隔离时另行确认。
- 隐藏到托盘后是否默认继续运行、静默时是否允许自主唤醒。
- 希望同时活跃的成员数量、自动聊天和工具的大致费用预算。
- 群主可以修改的“群参数”具体有哪些字段（四项权限及聊天平等原则已由用户确认，不再作为开放问题）。
- 生图、搜索、附件上传的首次授权和日常自动权限。
- 完整 V1 与 P0 演示阶段的边界、是否需要任意代码实际执行。
- 文件保留、备份内容、全文本是否需要本地加密。
