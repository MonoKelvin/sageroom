# Sageroom 模型接入与工具执行设计

> 版本：0.4｜状态：三协议网关、系统凭据、连接测试、取消与采样惩罚已实现；模型工具框架仍为设计目标且调用被拒绝｜日期：2026-11-26\

## 1. 边界与路线

`ModelGateway` 接受宿主构造的标准请求，交给具体 provider adapter，返回标准内容、usage、错误及必要协议状态。它不决定角色性格，不发布群消息，不执行任意工具，也不自动换提供方。

推荐以 Rust 为运行时，条件采用 Rig 的 provider/消息/结构化输出能力。只复用能经过合同测试的模块，不引入整套 CLI harness；某项协议不适配时只补窄 adapter。Rig 的具体 API 按锁定发布版本验证，不复制 main 分支示例作为稳定实现。

每位智能体仍是 SKILL + 自己的模型配置副本；SDK 负责网络/协议，不接管群成员是否发言的规则。重试、付费操作和工具步骤必须在宿主可观察的边界执行，不能隐藏在无限 `agent.run()` 循环中。

## 2. 配置、复制与共享

### 2.1 配置分层

| 对象 | 内容 | 生效规则 |
|---|---|---|
| ProviderProfile | 协议、base URL、API version、模型 ID、能力记录、价格、secret_ref | 全局可选模板，非敏感字段版本化 |
| AgentModelSnapshot | 复制的模型 ID、端点、采样/思考/预算等普通参数及来源模板版本 | 独立修改；全局改模板不静默覆盖 |
| CredentialRef | OS store 索引、绑定 endpoint fingerprint、是否配置 | 引用共享，不复制 API Key |
| ImageProfile | 图片协议、模型、尺寸/数量支持、任务查询、计费 | 与聊天模型分开，成员显式选择 |
| SearchProfile | 搜索服务、结果/正文能力、价格、域名策略 | 搜索和正文提取分开 |
| PersonalityPreset | 公开人设、语言维度、SKILL 内容 | 采用时复制成成员版本 |
| ToolGrant | 成员/工具/endpoint/数据范围、一次或持续授权 | 本地用户建立，不因群主或模板复制而扩权 |

“引用全局配置”体现在选取模板和来源关系；普通参数默认复制。图片/搜索设置也在启用时解析为有效快照。公共凭据更新影响全部引用它的快照，UI 必须提示共享关系。

端点改变是新的数据外传目的地：旧授权和能力测试不能直接继承，重新绑定凭据/授权。禁止模型自行把请求切到新域名或任意请求路径。

### 2.2 端点规范化

协议枚举至少区分 `openai_chat_completions`、`anthropic_messages`；`openai_responses` 仅在单独 adapter 通过测试后可配置，不当作前者别名。

base URL 由对应 adapter 的明确规则处理路径前缀，UI 预览最终 endpoint，避免重复 `/v1` 或偷偷尝试多个路径。HTTPS 为默认；本地或指定内网模型须显式授权，且不能把该例外扩展给搜索网页抓取。

额外 provider 字段走该 adapter 的白名单。不能接受自由 headers、任意请求 body 或任意 schema URL 从前端直接透传，尤其不得覆盖鉴权和权限字段。

## 3. 能力注册表

能力不是品牌标签，也不是 UI 勾选后就变成事实。

| 维度 | 描述/取值 |
|---|---|
| text | 文本 completion 支持 |
| structured_output | native_schema / tool_emulated / prompted_json / unsupported |
| tools | 原生调用、并行数量、schema 子集及与输出约束的组合支持 |
| vision | 支持格式、URL/bytes、尺寸与图片计数方式 |
| reasoning_control | explicitly_disable / between_tools / always_on / unsupported / unknown |
| reasoning_usage | 是否报告及是否包含在 output_total 中 |
| context/output limits | 已验证或资料声明的容量，不能默认无限 |
| streaming | SSE/非流式、终止语义、错误事件 |
| usage/cache | 成分、累计还是增量、缓存写读计费 |
| image_generation | 独立接口，不能由 text 或 vision 推导 |
| idempotency/cancel | 创建请求、任务查询、远端取消的支持范围 |

每项保存 `status=verified/declared/unknown/unsupported`、证据来源、测试时间、profile/model/API version 和适用组合。verified 只用于实际合同测试通过的精确组合；资料核实写 declared。

模型列表存在不证明 tools/vision/non-thinking 可用。测试某项能力的输入使用合成非敏感样本，不偷发用户最近聊天。用户知晓可能收费后显式启动；失败不把模型注册成全部支持。

## 4. `ModelRequest / ModelResponse`

### 4.1 请求

| 字段 | 来源与限制 |
|---|---|
| request_id / purpose | 宿主分配，分类 social_decision/revalidate/tool_step/summarize/memory_extract/profile_test |
| actor/task attribution | 当前成员及宿主 root_task_id/job ID；工具反馈/续步沿用已有预算根，不由模型伪造 |
| profile_snapshot | 有效非敏感 profile revision；secret_ref 仅 Rust 可解析 |
| context | 06 的 ContextBundle、data_generation_id、来源版本及范围；切根后拒绝旧回调提交 |
| response_contract | 当前 purpose 对应 schema_version 和 schema，04 是社交输出唯一基线 |
| capabilities_required | 文本/schema/视觉/工具/thinking 的必要组合 |
| reasoning_intent | off / enabled_for_complex_task，off 不等于隐藏显示 |
| limits | input、output、工具步数、请求总截止、提供方并发 |
| authorization / budget | 经验证的 grant revision、预留 ID、endpoint fingerprint |
| cancellation | 贯穿排队、网络、流解析、工具和提交 |

实际 HTTP body 是 adapter 的责任；不在 UI 保存带鉴权的完整请求，不把 provider 特有类型泄漏给聊天列表。

### 4.2 响应

包含 `request_id`、provider request ID、标准 text/decision、规范化 tool_calls、finish reason、usage、elapsed、warnings、必要的 opaque protocol state。

finish 分类：completed / tool_requested / length_limited / refused / cancelled / failed / unknown。HTTP 200 但含 provider error event、refusal、截断或空内容不能当作成功 decision。

- tool_calls 只是候选声明，不执行。
- token 流、tool arguments 和 JSON 全部解析完成后才能进入业务验证。
- `length_limited` 不能截出一个“看似合法”的工具参数就执行。
- `refused` 是独立失败/拒绝类别，不自动跨模型绕过。
- `opaque protocol state` 与群正文、长期记忆、诊断严格分开。

## 5. Provider 映射及资料核实

| 路线 | 接入设计 | 必须验证的边界 |
|---|---|---|
| OpenAI-compatible Chat Completions | adapter 明确 messages、response_format、tools 和扩展字段 | JSON object 不等于 strict schema；不同网关可能丢失 usage/额外字段 |
| DeepSeek 实际端点 | 原生支持的 OpenAI 格式或另一个明确协议，不混猜 | 关闭 thinking、reasoning_content 工具回传、采样支持、visual/schema 按模型核实 |
| Anthropic 原生 Messages | 独立鉴权、API version、content blocks、output_config 和工具回合 | 不用 OpenAI 兼容层宣称全部原生能力；不同模型 thinking/forced tools 有差异 |
| 本地/其他提供方 | 按明确协议配置，禁用未知能力 | 内网例外需授权，不能假设免费、无限上下文或相同 tokenizer |

### 5.1 普通聊天关闭思考

宿主要求 off 时，adapter 先检查该模型和 API version 是否真能关闭：

- 2026-11-18 读取的 DeepSeek 官方 Thinking Mode 页面说明，OpenAI 格式可用 `thinking.type=disabled`，Responses 格式用 `reasoning.effort=none`；页面当前说明默认启用 thinking。仅适用于该页面对应接口，不推广为所有历史模型。
- Anthropic 模型控制按实际版本核实；不是所有模型都接受 `thinking.type=disabled`。不能用降低 effort 或 omitted display 冒充 non-thinking。
- 必需 off 但能力 unknown/always_on 时，返回 `CAPABILITY_UNSUPPORTED` 并提示选择支持的模型；如果用户明确放宽该成员要求，创建新配置版本并显示仍可能思考/计费。
- 工具复杂任务可以用独立 thinking 设置，普通聊天不会因为某个任务复杂就永久开启思考。

不默认配置昂贵的固定品牌模型或 silently fallback；用户已有可用模型和预算优先。真实模型名称、价格和容量在连接测试及版本冻结时确认。

### 5.2 结构化输出

能力选择顺序为已验证的 native schema → 已验证的工具模拟 → 提示约束 JSON。降级需要明确标注保证程度，不能认为三者等价。

2026-11-18 读取 Anthropic structured outputs 页面，JSON 输出通过 `output_config.format` 指定 JSON Schema；strict tools 是独立能力，可以组合但受模型及 schema 限制。04 的应用 schema 先经 Serde/业务校验，再转成 provider 支持的子集；业务 enum、来源、ID、大小、权限仍在宿主检查。

遇到拒绝、max tokens 或 provider 组合不支持时，不能引用“总能合法 JSON”的宣传描述省略错误处理。prompted_json 非法输出最多按 P-RUN-09 修复一次，不把自由文本泄漏到群中。

### 5.3 协议历史与私有状态

DeepSeek 当前页面要求，带 tools 的 thinking 请求在后续回合回传此前的 `reasoning_content`，包括没有调用工具的回合。adapter 只在同一合法工具会话保留必需 state，不能抽取思维链写入消息或普通日志。

Anthropic 的 tool_use/tool_result、thinking/signature 等按该模型/API 原样要求维护；不是把当前群历史重排后随意拼回旧协议 state。换模型、改变语境、撤回/删除必需来源或授权撤销时结束旧会话，不为了保持协议而继续上传已失效内容。新回合可带真实工具 job 状态及仍合法的结果，不重复调用已完成的付费工具。

私有 state 默认内存保存；重启恢复确需持久化时必须加密、限期且再次授权，不进普通 params_json/备份。无法安全恢复时标 interrupted/ResultUnknown 并让用户核查，不能静默补跑。

## 6. 网络、流、超时和重试

### 6.1 请求阶段

`Validate → Reserve → Queue → Send → Parse → ValidateResponse → Settle → Return`。

每个实际 HTTP 尝试都有 attempt ID、发送阶段、可能计费标记和配额记录，对应 05 的 request_attempts。逻辑 request 聚合结果但不覆盖失败尝试的 usage/unknown；SDK 默认重试应关闭或与宿主策略一体化，防止“宿主 3 次 × SDK 3 次”。重试也要重新预留并记录；排队取消仅释放未发送预留，已发送未知尝试保留不确定性。网络 retry 不是社交随机唤醒。

SSE 使用维护中的标准解析能力；支持 UTF-8/JSON 跨分片、增量工具 arguments、心跳、终止和错误 event。断流没有最终 stop 标记时为 unknown/failed，不将收到的半句作为成员已发送内容。社交先验证完整 JSON，再以正常气泡发布，而不是直接显示 JSON token 流。

### 6.2 错误政策

| 情况 | 自动处理 | 成员/任务状态 |
|---|---|---|
| 401/403、明确余额不足 | 不重试，凭据/账务需修正 | 已配置成员 Offline，带一次昵称标记 |
| 模型/关键能力不存在 | 不盲试别名或其他提供方 | NeedsConfiguration 或 Offline 的可行动原因 |
| 429 | 在总截止内遵守 Retry-After；有界尝试 | 先 ErrorBackoff，耗尽 Offline；全局配额则 Protected |
| 5xx/连接故障 | 按 endpoint 策略及可能计费边界有限重试 | 耗尽 Offline；所有尝试归账 |
| 已发送后超时/断流 | 标可能计费；语言重复调用也计入配额 | 社交不发布半结果；工具付费创建 ResultUnknown |
| schema 无效/截断 | 最多一次结构修复，非危险动作不执行 | 失败保留诊断；连续不能产出合法决策可 Offline |
| 本地暂停/退出 | 取消本地等待和未发动作 | Paused/Stopping，不标故障离线 |
| 本地预算/风暴上限 | 直接阻止新请求 | Protected，不标性格沉默或 provider 离线 |

退避是短且有界的网络重试策略，参数引用 P-NET-02；超过截止不等待到无限未来。工具创建是否幂等单独判断，不能套语言请求的重试规则。

Offline 故障周期持久化，标记消息只提交一次；点击重试上线须重新验证必要能力与用户启用条件。不得每个模型错误唤醒整个群，具体合同见 04。

## 7. 工具授权与任务合同

### 7.1 触发和明确意图

工具成员仍可记录所有消息高水位，但不为每句普通闲聊调用 LLM。同伴委托只消费已提交消息/通告的结构化提及事件，先持久化唯一 `(origin_message_id, target_agent_id)` 意图处理键；事件重放、@all 与单独提及重合均不重复判断或创建任务。没有明确任务时记录追问/拒绝/无任务结果，不按关键词预判。

普通成员不必把自己的能力委托给另一成员：04 的 tool_requests 为自身获准工具请求，绑定 origin_decision_id/action ID；同一请求不再生成第二条同伴委托入口。社交/工具类型只改变无任务时的调度偏好，不限制具备能力的成员使用自身 ToolRunner。

用户和普通成员都可以委托，群主没有额外工具权。模糊请求先追问或拒绝；语义识别由接收成员模型完成，代码不以关键词决定“这是生图任务”。本地授权决定可不可以花费/联网，不决定该任务是否值得回应。与现有任务相关的续问由模型关联已有 task ID，不因每条进度/续问盲建新任务；新付费动作仍需独立授权与幂等检查。

### 7.2 `ToolJob`

宿主字段：id（job ID）、root_task_id、actor_id（执行能力的成员）、origin_message_id / origin_decision_id（至少一项真实来源）、root_chain_id、depth、tool_profile_revision、validated params、authorization revision/approval hash、budget reservation、remote_job_id、state、cancel_state、result reference、result_message_id。自主机会可以没有来源消息，但必须绑定有效 decision 与已有授权；模型不能编造 origin ID。

意图判断、能力执行及结果反馈使用一个任务预算：最多 P-TOOL-01 次模型步骤，含初次请求、修复和最终反馈；网络重试另计全局实际请求配额。社交 decision 已发起自身工具时计作初次步骤，不再强制重复一次意图判断。每次外部工具动作逐项扣额，本地只读检索也限制次数/体积但不冒充外部付费单位。

初次有效工具请求由宿主创建 root_task_id 和持久 task_budgets；同决定的多个请求、原生 tool_calls、结果反馈 decision、续步及同任务的子委托都沿用该根和剩余额度。ToolJob 是该根下的一次具体能力动作；反馈 envelope 与 ModelRequest 的 root_task_id 由宿主填写，模型不能通过新 decision_id/action ID 创建新预算。每一步在原子事务中扣同一根计数，达到限制就停止；只有新的独立外部任务机会才可建立新根，工具结果/自己续步不能作为新根来源。

每次批准绑定 `(task ID, actor, tool, endpoint, normalized params hash, data scope, maximum units, expiry)`。参数、端点或数据范围变化重新批准；不能先批准“查新闻”再暗中生图或上传图片。

```text
Created → AwaitingApproval → Queued → Running → Succeeded / Failed
                                  └ CancelRequested → Cancelled / ResultUnknown
Running → ResultUnknown → Succeeded / Failed / Cancelled（仅有真实核查依据）
```

`CancelRequested` 是处理中；`ResultUnknown` 表示远端状态或费用无法确认。`Succeeded` 仅指工具结果已取得并落地验证，不等于结果已经在聊天室发布；发布状态另用 result_message_id/action 幂等管理。

### 7.3 执行顺序

1. 验证来源未撤回、成员/工具 grant、任务参数、深度及单位上限。
2. 缺许可则 AwaitingApproval；明确拒绝结束，不后台自授权。
3. 事务预留工具/模型额度，进入有界队列。
4. 运行前再次校验授权、取消、source 和 config version。
5. 每个外部动作分别计数，越界则停止；并行动作也不能绕过总上限。
6. 结果经过 URL/内容/解码限制，文件落地成本地 attachment ID。
7. 保存终态、真实 usage 及 remote ID，给工具成员新的合法结果语境。
8. 工具成员选择如何反馈结果；应用状态卡可直接显示已完成但不伪造模型正文。结果消息以独立幂等动作提交。

执行完工具但发布失败：只重试本地保存/发布，不重新请求生图或搜索。同伴委托延续根 chain ID，不以工具结果创建新根清零自动聊天限额。

## 8. 首版工具目录

| 工具 | 输入 | 标准输出 | 权限/边界 |
|---|---|---|---|
| `web_search` | query、有限结果数、明确语言/日期/域名条件 | 标题、真实 URL、snippet、来源、检索时间、发布时间可空 | 网络 grant；无法兑现 recency 时返回 filter unsupported，不伪装已筛选 |
| `web_extract` | 先前真实来源 URL、有限正文范围 | 正文片段、取得时间、final URL、不完整标记 | 网络校验、重定向与字节限制；网页不带权限 |
| `image_generate` | prompt、能力支持的尺寸/数量、允许参考 attachment IDs | task/job state、本地附件 ID、实际数量及费用边界 | 付费及图片外传授权；未确认幂等时创建一次 |
| `expression_evaluate` | 有限表达式 | 数值/合法错误、单位可空 | 受限解析器，无 eval/shell，操作数/深度限制 |
| `code_draft` | 语言、说明、有限上下文 | 安全展示的代码文本及必要说明 | 使用模型请求预算，首版不执行或安装依赖 |
| `history_search` | 关键词、有限日期/成员范围、limit | 有来源的有效片段及 ID | 当前聊天室授权范围，无 SQL 透传 |
| `memory_query` | 当前 owner 的主题/实体条件、limit | 当前成员/公开群 valid 记忆及来源 | 06 的 scope/失效校验，不任意指定 owner |

工具结果带 `source_kind`、`retrieved_at`、`truncated`、`warnings` 和安全的 error code。模型不能凭空造 object ID/下载链接补上空结果；invalid IDs 要报错。

本地 history_search/memory_query 使用宿主固定的当前聊天室/owner 范围，无远端传输时不要求额外网络许可，但结果若送给模型仍受该提供方外传授权。外部能力与社交/工具类型独立配置；工具成员只减少无任务的聊天调用，不垄断生图或搜索。

### 8.1 图片生成

支持同步 URL/base64/bytes 和异步 job ID 两类 adapter。同步也可能已经执行付费；断网不自动重发。URL 下载经每次重定向/目标 IP/类型/流大小校验；base64 也按解码后字节限制。远端文件未落地前不发布为成功图片。

异步 poll 是查询已经创建的同一个 job，不是新建任务；退避和截止引用 P-NET-03，按 provider 的 poll 费用/限额归账。查询超时保留 remote_job_id 和 ResultUnknown，可显式核查。用户取消不保证 provider 支持取消或退款。

参考图仅能来自本次授权附件对象，mask/编辑等不支持能力不自动降级成别的操作。不要用模型自由 URL 下载任意本机/内网资源。

### 8.2 搜索与热点

只有真实搜索才称“查到”；发布时间不确定就标未知，检索时间不是发布时间。摘要保留来源及分歧，不把 provider 自带置信值当事实认证。

主动热点机会可以使用已经授权、已缓存且不过期的资料；成员提出搜索时仍经过同一工具权限和配额。无资料时可说不知道，不能凭训练知识生成“今日新闻”。不默认每位成员循环检索新闻。

### 8.3 表达式与代码

计算库在版本冻结时选择维护中的受限解析器；限制输入长度、嵌套、数值范围和执行时间，不允许用户定义函数、文件访问或循环。除零、溢出、NaN 等采用一致错误合同。

生成代码视为消息文本/附件，安全高亮、复制、另存；任何语言代码均不自动执行。未来沙箱执行需要新需求与权限设计，不把“代码生成”偷偷扩成访问 shell、安装包和联网。

## 9. Usage 与预算账本

### 9.1 计费成分

usage 保存成分名、值、单位、来源 measured/provider_reported/estimated/unknown、是否已经包含在 total。输入未缓存、缓存读、缓存写、输出、reasoning、图片、搜索 credits 各自记录。

不能把 reasoning 再加到已含 reasoning 的 output_total；不能把整个 SSE 的每次累计值相加；没有 usage 不能记成零。provider request ID 和 price_revision 支持核查，但应用估算不是最终账单。

### 9.2 预留与结算

- 每个实际尝试发送前在串行事务中建立 reservation/attempt 并占用配额；逻辑 request 只作为归属，不能只按最终成功请求计一次。排队仅保留有界预留，未发取消释放；发送前的保守占额遇崩溃按未知处理，不能丢记录后再无限请求。
- 价格已知时按上限估算预留；未知价格使用请求/工具单位额度，金额保护显示不完全可估。
- 成功取得 usage 后结算并释放明确未花费部分；结果未知保留未确定预留及可能计费标记。
- 取消之前已经 send 的请求不能立即当零；重启继续标 unknown，查询/用户账单核查后解决。
- 不因 reservation 过期就忘掉可能已执行的收费；过期的排队未发送请求可释放，已发送未知请求需独立保守归账政策。
- 每个币种独立预算；未经用户配置汇率不直接相加。默认配额引用 P-RUN/P-TOOL。

日配额采用宿主持久窗口，默认 UTC 日边界见 00，小时/min 为滚动窗口。时间异常不能通过改系统日期重置预算或恢复无限调用；保留最后窗口和保守保护，细节见 09。

### 9.3 用户展示

分别展示决策（含沉默）、结构修复、网络重试、归纳/记忆、工具后续、生图/搜索；未知项、估算币种和资料日期可见。总暂停立即阻止新预留请求，不只停住气泡动画。

## 10. 测试矩阵与采用门槛

每个候选 adapter 至少测试：文本/schema、off thinking、vision、tools、tools+schema、usage、429/401/5xx、SSE 截断/错误、取消、超时、重试次数和可能计费标记。仅启用该成员实际需要且通过测试的组合。

Rig 采用门槛：宿主能拦截每次请求和工具调用、限制步数、取消、读取 usage、保留必要 state、设置 provider 扩展参数，且不要求引入额外常驻 CLI/runtime。若锁定版本无法满足，记录阻塞项并优先补窄 adapter；引入 TS sidecar 或改变架构需要重新确认。

当前只有公开资料核查，不存在 verified provider/价格/费用。测试 IDs 和实际执行记录模板在 10、实施工作包在 11；不能把官方示例或 Context7 片段标成本机模型测试通过。
