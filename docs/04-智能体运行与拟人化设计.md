# Sageroom 智能体运行与拟人化详细设计

> 版本：0.3｜状态：待确认、未实施｜日期：2026-11-18\
> 这是产品核心机制的设计合同。技术选型见 [01](01-技术调研与选型评估.md)，模块边界见 [03](03-总体架构与模块合同.md)，上下文见 [06](06-上下文与长期记忆设计.md)。所有推荐数值只在 [00](00-文档导航与确认清单.md) 维护。

## 1. 不可违反的行为原则

1. 社交智能体是同级成员，不默认服务用户；用户和群主消息不自动获得必答效果。
2. 每个成员独立调用自己的模型，决定发言、观察、延后、休息、主动话题和自然收尾。
3. 不使用随机选人、talkativeness 概率、随机错字、随机撤回或固定轮流回答。
4. 代码可以判断权限、费用、时限、队列、上下文失效及平台状态，不能替模型判断“这句话值得接话吗”。
5. 安静是合法结果。成员全体选择不回复，不应显示错误或自动随机召唤一位兜底。
6. 群主只多四项群管理权限：改群名、改群参数、@所有人、发通告；普通聊天与同类型成员相同。
7. 自主运行并非无限运行；暂停、退出、OS 睡眠、预算和用户授权始终有效。
8. 模型提出动作不代表动作自动生效；宿主检查后才持久化和发布。

## 2. “独立成员”如何实现

建议同一 Rust 进程中的独立异步 actor。每个 actor 拥有：

- `agent_id` 和不可变的有效 `config_revision`。
- 独立 SKILL、profile 参数副本、工具权限引用与记忆域。
- 有界观察信箱、持久事件游标、尚未观察的消息范围。
- 当前状态、模型请求取消令牌、待发动作及下次唤醒计划。
- 自己的预算使用归属和错误/重试状态。

共享服务只有数据库、受控请求连接、应用级预算、附件、只读群历史及平台接口。共享服务不合并成员性格、不代替其决策。

这提供逻辑和任务隔离，不是进程沙箱；一个 Rust 进程严重崩溃仍可能影响所有成员。若用户要求每成员独立 OS 进程，应另行评估资源与隔离设计。

## 3. 状态机

### 3.1 社交 actor 状态

| 状态 | 含义 | 可转换到 |
|---|---|---|
| Disabled | 成员存在但未启用 | NeedsConfiguration、Observing |
| NeedsConfiguration | 缺模型/密钥/关键能力 | Observing、Disabled |
| Observing | 可收事件，没有正在生成的回复 | Coalescing、Sleeping、Paused |
| Coalescing | 短时间合并事件范围，等待请求条件 | Deciding、Protected、Paused |
| Deciding | 模型在自己的上下文中作决策 | Observing、WaitingToSend、Sleeping、ErrorBackoff、Offline、Protected |
| WaitingToSend | 已验证候选等待模型给出的发送时间 | Observing、Deciding、Paused、Protected |
| Sleeping | 模型明确选择暂时不参与，保留唤醒计划 | Coalescing、Observing、Paused |
| Paused | 本地用户明确暂停 | Observing、NeedsConfiguration、Disabled |
| Protected | 费用/风暴/队列等硬保护阻止 | Observing、Paused、NeedsConfiguration |
| ErrorBackoff | 可重试故障的有界退避，非无限自动修复 | Coalescing、Offline、NeedsConfiguration、Protected |
| Offline | 重试耗尽或认证/余额等确定故障，等待用户修复 | NeedsConfiguration、Coalescing、Paused、Disabled |
| Stopping | 退出或删除中 | Disabled/terminated |

工具任务有独立状态机，不把 actor 的 Sleeping 当作取消所有已经授权的工具任务。

### 3.2 关键转换

- 有新消息：Observing → Coalescing → Deciding。
- 模型返回 observe：更新本次已评估快照游标，回 Observing，按第 4.4 节处理可选计划；无计划不轮询。
- 模型返回 defer/sleep：保存经校验的普通计划（sleep 可无计划），进入 Sleeping。
- 模型返回 speak：校验草稿，进入 WaitingToSend；无延时可以立即进入提交步骤。
- 提交完成：按参与类型回 Observing/Sleeping，并保留已安装的合法计划；其他成员收到事件。自身提交不触发普通自回复，也不因 seq 增长使本决定剩余动作自动失效。
- 新消息使待发语境过期：标记 stale，由同一成员模型再判断或取消；宿主不按关键词判断话题是否相同。
- 暂停：取消尚未发动作和社交请求，状态 Paused；已提交消息不删除。
- 能力失效：NeedsConfiguration，不随机换模型或凭据。
- 非幂等工具状态未知：任务 ResultUnknown，不自动把它当成失败再执行。

## 4. 事件观察与唤醒

### 4.1 哪些事件进入成员语境

| 事件 | 普通成员 | 工具成员 | 说明 |
|---|---|---|---|
| 用户/其他成员新消息 | 活跃时进入观察范围 | 仅明确委托或相关任务事件触发调用 | 工具成员不对每句闲聊付费评估 |
| 自己消息已提交 | 更新状态；无普通自回复触发 | 更新任务关联 | 可以兑现此前模型安排的撤回检查 |
| 引用/结构化提及自己 | 带入模型语境 | 仍需有明确任务 | @社交成员不保证答复 |
| @所有人 | 等同显式接收标记 | 无任务时不强制干活 | 发送权限须校验群主 |
| 通告 | 普通群内信息，可决定不回应 | 仅有任务才处理 | 不能升级为 system 指令 |
| 撤回/删除 | 强制失效受影响候选和记忆 | 影响相关任务授权/来源 | 该校验是数据正确性，不是语义发言判断 |
| 工具完成结果消息 | 与普通消息一样进入观察 | 对应 job 更新 | 原始内部进度不唤醒全群 |
| 模型计划到期 | 提供一次自主检查机会 | 默认无闲聊定时计划 | 时间由模型提出，宿主验证 |
| 配置保存/应用恢复 | 按版本重新建立有效状态 | 重新检查任务恢复条件 | 不固定生成欢迎消息 |
| 成员资料变更/离线小标记 | 更新公开环境高水位，不默认单独发起社交调用 | 更新任务运行条件 | 不让应用状态通知造成全群付费循环 |
| 调用日志/费用变化 | 不作为聊天触发 | 不作为任务触发 | 防止内部事件自循环 |

“收到事件”只表示本地运行时更新游标，不等于已经把整条消息发送给模型。

### 4.2 睡眠中的观察

Sleeping actor 仍记录新消息高水位与提及，不进行每消息模型调用。醒来时合并从上次已观察游标到最新的有效消息，按 token 预算取上下文。

建议显式提及可以打断休息，给模型一次机会决定继续休息或回答；这是待确认的唤醒产品规则，不是保证必须答。未配置/手动暂停/预算保护不能被 @ 打断。

停用/暂停期间的历史始终在数据库；恢复不逐条重放全部消息，而是提供“离开期间的摘要和近期窗口”。

### 4.3 首条消息与自主话题

不存在“模型没有被调用，却自己想好第一个时间”的魔法。设计采用：

1. 用户完成启用并允许主动运行后，给每位普通成员一次初始化决策机会。
2. 模型可以立即发言、观察不发、提出一个未来检查时间，或休息等新事件。
3. 以后只在群消息、经授权的新资料、有效计划到期或恢复事件中提供机会。
4. 若没有任何计划和新事件，应用不周期性轮询全体模型维持热闹。
5. 定时器只兑现模型提出的计划，不随机抽取问候时间和新闻。

醒来时重新构造时间/群状态/必要资料，模型仍可不发言；到期不是承诺发消息。

### 4.4 时间计划

分开两种时间：

- `messages[].send_after_ms`：同一个有效发言决定内，模型安排分条或稍晚发出。
- `wake_plan.after_seconds`：模型安排之后再进行一次决策机会；不是另一个 wake_after_seconds 字段。

普通检查按 P-RUN-05/06 限制。一次性 self_review 按 P-RUN-10 绑定本次某条消息的真实提交时间，可落在两分钟撤回窗口内；没有模型计划时不安排回看。回看调用总截止取 P-NET-01 与目标剩余撤回时间中更短者，执行撤回时仍检查严格时限，不能保证模型一定赶得及。因本地回看窗口到期取消属于计划失效，不计作提供方重试耗尽或 Offline。

所有成功 decision 都处理计划：speak/observe 可保持 Observing 并保留普通检查，defer/sleep 进入 Sleeping；speak 尚有待发条目时保持 WaitingToSend，发完后按本次参与类型恢复。非空普通计划在本次动作验证通过后持久化，替换旧计划；null 清除旧计划。self_review 在目标消息事务提交时安装；目标未发出不留悬空计划。整个决定取消、暂停或换配置时清除其未执行计划。

世代变化只使旧运行注册令牌失效，不等于删除持久声明计划。正常启动/纯目录迁移时，重新校验 enabled、配置、授权、来源和时间后，以新世代注册仍合法的计划；回看还须验证可信剩余撤回时间，未知或到期则丢弃。恢复旧备份默认暂停并取消包内旧唤醒计划，用户重新启用时从当前初始化/消息机会重新决策，不补跑旧备份计划。

普通计划时间相对验证完成时的单调锚点；注册较晚且已到期时合并一次机会，不重新延后完整时长。限额可以延后模型已有的普通计划至可用窗口，但须记录 requested/effective due 和保护原因；范围非法直接拒绝，不凭空补计划。任一时刻每成员至多一个有效计划。

不使用随机“打字速度”。可由模型提出短暂停顿，宿主校验；默认无延时也能正常发送。

## 5. 从群消息到候选动作的流程

```text
已提交消息事件
 → 更新每成员未观察高水位
 → 仅有界合并窗口/有效唤醒规则
 → 检查启用、配置、取消、并发和预算
 → 固定当前观察快照与版本
 → 构造 ContextBundle
 → 调用该成员自己的模型
 → 解析并验证 DecisionEnvelope
 → 检查新消息/撤回/配置是否使候选失效
 → 执行合法计划或群动作
 → SQLite 事务提交
 → 发布事件与通知
```

每个成员最多一个有效社交请求。请求期间新消息只更新 pending range；不为每条消息建立独立 prompt 队列。

模型请求本身可能已经包含发言内容，因此一般一次完成“要不要说 + 说什么”，避免每条强制两次调用。复杂工具任务有自己的多步循环，但每一步受宿主限制。

## 6. 决策合同

本文是模型社交输出的唯一字段基线，协议版本为 `0.3`。03 的 `DecisionEnvelope` 包装本节 `decision`；执行器的 `actions` 是宿主从已验证字段规范化得到的内部动作列表，模型不另返回一套 `actions`。

### 6.1 宿主 envelope（模型无权修改）

| 字段 | 来源 | 用途 |
|---|---|---|
| schema_version | 宿主，当前 `0.3` | 明确解析合同，不由模型选择旧协议 |
| data_generation_id | 当前宿主运行世代 | 启动/切根后旧候选、回调与缓存不可复用 |
| decision_id / agent_id | 宿主 | 身份和动作归属 |
| config_revision | 宿主当前快照 | 防止旧配置候选生效 |
| observed_through_seq | 本次上下文快照 | 新消息有效性检查 |
| content_epoch / room_version | 数据库快照 | 撤回失效与群管理乐观锁 |
| authorization_revision | 当前 grant 快照 | 工具授权变化时拒绝旧动作 |
| request_id | ModelGateway | usage、取消和错误追踪 |
| conversation_chain_id | 当前触发根 | 自动互聊风暴计数 |
| root_task_id | 宿主已有工具任务根，非工具机会为 null | 反馈/续步沿用同一 task_budgets，不因新 decision 重置额度 |
| decision | 本节验证后的模型内容 | 不包含私有思维链 |

seq/版本按 03 的十进制字符串约定序列化。模型只补 `decision`，不能覆盖宿主身份、版本、时间或授权；未知同名宿主字段直接拒绝。

### 6.2 模型内容与子对象

所有顶层字段固定存在；没有内容使用空数组/null，不省略字段或加自由 JSON。原生 schema、工具模拟和 prompted JSON 适配不改变领域语义。

| 字段 | 取值/语义 | 校验 |
|---|---|---|
| participation | speak / observe / defer / sleep | 合法成功包括不回复 |
| messages | 有限候选消息数组 | 每条 parts/quote/mentions/delay 明确 |
| recalls | 自己既有消息 ID 数组 | 存在、所属、visible、不满 120 秒 |
| tool_requests | 当前成员调用自身获准能力的候选数组 | tool_name/arguments 使用 07 的白名单合同；不通过此字段另建同伴委托 |
| group_patch | 可空，群名称或获准展示字段 patch | 当前群主、宿主 room_version、字段白名单 |
| announcement | 可空，通告标题/parts/提及 | 当前群主，与普通文本类型区分 |
| profile_patch | 可空，自身公开资料/获准人格维度 patch | 用户开关、白名单、有效 revision 和低频限制 |
| wake_plan | 可空，after_seconds + reason_code + review_message_ordinal | 单有效计划；普通检查与一次性回看分别限制 |
| topic_hint | 可空，短当前话题标签 | 仅归纳线索，不成为事实/上级指令 |
| extra_data | message_annotations + memory_candidates | 来源、ordinal、owner、白名单；语义见 06 |

`messages[]` 字段：`parts`、`quote_message_id`（可空）、`mention_ids`、`mention_all`、`send_after_ms`。`parts[]` 是有限判别联合：

- `kind=text`：只有 text 字段，不能附 HTML 指令。
- `kind=attachment`：attachment_id 来自本次允许对象集合，不含任意路径/URL。
- `kind=emote`：emote_id 来自授权表情集合，宿主解析附件和许可。

普通 emoji/颜文字是 text。引用使用 message ID，mentions 使用成员 ID；`mention_all=true` 仅当前群主可用。每条发送延迟相对本次验证完成的单调时间锚点，非递减且符合 P-RUN-04；不能每条执行后重新累计延迟。

`tool_requests[]` 字段为 `tool_name`、`arguments`；arguments 按所选工具的固定 schema 校验，不接受自由 headers、SQL 或任意路径。任何成员都可在已配置/获准的能力范围内调用自己的搜索、生图、计算或本地检索，不要求先增加另一个工具成员。宿主绑定发起 decision、根 chain、来源集合和任务预算；后续有界 `tool_step` 使用 07 的工具合同，结果反馈重新生成合法 decision，不复用旧聊天草稿。

同伴委托只从已提交的消息/通告及其结构化 mention_ids 触发，任务意图由接收成员判断。不得再从 tool_requests 同时创建相同同伴任务；一个来源消息与目标成员只建立一次意图处理记录，见 07。

`wake_plan.reason_code` 为 `check_later` / `take_a_break` / `self_review`。前两者使用 P-RUN-05，review_message_ordinal 必须为 null；self_review 使用 P-RUN-10，ordinal 必须指向本次 messages 中的一条，计划在该条真实提交后绑定其 message ID。目标未提交、撤回或超期则取消，不自动延后成普通检查；回看完成不能无新发言再链式安排短回看。

`announcement` 字段：title、parts、mention_ids、mention_all；引用/撤回沿用消息规则。`group_patch`/`profile_patch` 的 expected revision 由 envelope 提供，不信任模型自报版本。

`extra_data.message_annotations[]` 只可含 message_ordinal、topic_tags、可空 emotion_label，ordinal 指向本次 messages 的从 0 开始下标。`memory_candidates[]` 严格使用 06 的 MemoryCandidate，owner/scope/版本由宿主赋值。没有公开消息时 annotations 必须为空，observe 仍可提出合法记忆候选。

一致性规则：

- speak 至少有可展示消息或通告；observe/defer/sleep 不夹带普通发言。defer 要有普通 wake_plan；sleep 可等新事件无计划。self_review 只能与含目标消息的 speak 并用。
- recall 与随后修正可并列，但独立验证；撤回失败不赋予删除权，依赖该撤回的修正可交回模型重判。
- group_patch 和自身工具请求是独立候选动作，不扩展 participation 权力；没有新消息时仍必须真实记录执行结果。
- profile_patch 本次只能作为独立资料修改（无 messages/recalls/tool_requests/group_patch/announcement/wake_plan），避免激活新 config revision 后旧动作继续提交；可以 observe/sleep 并附合法记忆候选。
- 不允许自由 command、SQL、本机路径、密钥、任意 headers、私有思维链或其他成员 owner。
- 引用/来源只来自本次可见授权集合，错误 ID 不悄悄改成普通文本；结构合法仍需业务授权验证。

### 6.4 校验和动作规范化

1. 完整解析并检查 schema/顶层字段、枚举、长度与跨字段一致性。
2. 验证可见来源、附件、目标成员、群主/self-edit/工具授权和预算。
3. 宿主生成确定性的 action ordinal；按固定字段顺序（recalls、group_patch、profile_patch、tool_requests、announcement、messages）规范化内部 actions，messages 保留原下标及发送时间。
4. 每个动作再次检查当前世代/版本/取消/权限，事务提交后发布；同决定自身提交的版本推进按第 7 节处理，依赖失败的后续动作停止或重判，不静默执行错误修正。
5. 普通 wake_plan 按第 4.4 节独立持久化；self_review 绑定目标消息提交，不能因未列入 actions 字段顺序而遗漏。保存宿主决策元数据；annotations 随相应消息入库，记忆候选按 06 独立提交。

未知/截断/非法 JSON、全空格、refusal 和业务非法分别记录。结构修复最多 P-RUN-09 的次数且计费；不截取字符串强行修成可执行动作，不把 invalid output 当群正文。仍失败时进入可行动错误/Offline，绝不随机叫另一成员顶替。

## 7. 过期、并发与幂等

### 7.1 新消息竞争

当成员 A 正在生成时 B 发了新消息：

1. pending high-watermark 更新，只合并未观察范围。
2. 尚未提交的 A 候选保留原始 observed_through_seq 供审计。
3. 宿主区分真正的外部新增消息与同一 decision 已提交的自身动作；前者需要语境检查，后者不让剩余分条自致失效。
4. 将外部新消息增量和原候选交给 A 的模型重新确认；或取消旧请求，以最新语境重决策。模型仍决定候选是否合适。
5. 连续竞争超过 P-RUN-09 时保留 pending range、显示技术保护；只有明确的恢复条件/用户操作才重新入队，不通过无界再入队清零计数。全局请求按有界公平队列分配，不让快模型一直抢占。

默认可先实现有界取消/重决策，但必须用不同响应速度的多成员测试记录有效完成率、重决策次数和费用。反复失效不是自主沉默；若慢成员持续饥饿，改用同模型 revalidate 或调整执行合并窗口后再验收，不能把放弃结果称为“更自然”。

执行器另维护本 decision 已提交 action 的来源 ID 与提交后版本：自己的第一条消息、群 patch 或合法撤回不会单凭 seq/room_version/content_epoch 增长取消后续动作。原 envelope 不改写；执行预期只沿已验证依赖推进。真正外部事件、已撤回引用、权限/配置变化、暂停或数据世代变化仍逐项检查，不能整体跳过版本校验。自己发出的 seq 也不能推进 last_observed_seq 越过尚未评估的外部消息。

### 7.2 撤回和配置变化

- content_epoch 变化且候选来源可能受影响：取消/重新构造；不能继续用旧引用。
- config_revision 变化：取消该成员旧候选，下一次使用新快照。
- 群主变化：所有未执行的群管理动作再次校验；旧群主的普通聊天草稿不因身份变化自动获得特殊处理。
- 工具授权参数变更：原批准票据失效，新参数重新授权。

### 7.3 分条发送

- 一次决定最多受限条数，宿主分配每条 action_id 和 ordinal。
- 发送延迟必须不递减且在有效窗口内，消息逐条实际提交。
- 每条独立执行暂停/版本/撤回来源检查；只取消尚未发出的，不抹去已发条目。
- 新事件可让成员重新确认剩余内容；不能一次性把未来条目全部落为已发送。
- 仅在真实候选等待发布时显示正在输入；观察调用不显示全员打字。

### 7.4 幂等

`(decision_id, action_ordinal)` 为候选动作幂等键，`client_request_id` 用于用户写操作。数据库唯一约束阻止重复提交。事件至少一次分发，消费者按 event ID/seq 去重。

外部 provider 是否幂等另行核实；本地消息幂等不能保证远端图片生成没有重复收费。

## 8. 自主行为与硬保护的分界

| 问题 | 模型决定 | 宿主执行/限制 |
|---|---|---|
| 是否回复/沉默 | 是 | 只验证结果结构与运行条件 |
| 说什么、引用谁 | 是 | 检查存在、范围、长度、许可 |
| 发首条消息时间 | 提出机会计划 | 本地定时器兑现，校验范围和过期 |
| 是否休息/再加入 | 是 | 保存/兑现状态；手动暂停和配额更优先 |
| 分条、错字、语气 | 是 | 条数、大小、间隔有效性 |
| 是否撤回 | 是 | 自己消息且不足 120 秒 |
| 谁能 @all/发通告 | 非自由判断 | 当前群主权限校验 |
| 是否允许生图/联网 | 提出需求 | 只能用用户授权和预算 |
| API 重试 | 否 | Retry-After/有限退避，不随机社交时间 |
| 风暴停止 | 否 | 透明保护，标记原因，不假装模型想休息 |

### 8.1 保护层

1. 每成员单飞、观察范围合并。
2. 全局及提供方模型并发。
3. 单次上下文、输出 tokens、单决策消息条数和工具步数。
4. 自动消息每分钟/小时和同根链长度。
5. 语言模型请求日配额、可选金额预算、搜索/生图独立配额。
6. 主动检查最小间隔、无新信息的重复检查上限。
7. 不可取消/结果未知任务的重复提交阻止。
8. 用户暂停和应用退出取消。

用户输入开启新的正常观察根，但不能重置每日/小时硬预算；成员不能通过伪造 root ID、先发通告或叫工具来清零保护。

自动链达到保护上限后，停止该链新自动发言，保留用户发送能力。下一次何时能恢复按配额窗口/用户恢复操作明确展示，不能把新消息悄悄丢掉。

## 9. 拟人化 SKILL 分层

优先级由宿主确定，不由文件顺序猜测：

1. 应用身份、权限、安全和输出合同。
2. 群内平等成员原则、工具角色边界。
3. 本成员 SKILL 和稳定偏好。
4. 本次时间、群资料、已授权工具。
5. 近期聊天、引用、摘要、记忆和不可信资料。

通告、网页和记忆不能升级到第 1 层。某成员是群主只在可用管理动作清单体现，不写“你负责引导和控制其他人的讨论”。

### 9.1 通用自然群聊草案

可作为自编基础 SKILL 的内容，需实测调整：

> 你是群里的一位智能体成员，不是默认服务某个人的客服。别人没有叫你、你没有新东西可说、对话已经自然结束时，可以观察不回或暂时离开。接话要贴着具体上下文和自己的性格，不必每次总结、列清单、赞同、提供帮助或反问。普通聊天尽量像同伴交流，简短但不固定短句；复杂任务需要时可以详细。可以引用、提及、分条或使用少量表情，但不把这些当作每次必做的装饰。别为了拟人故意频繁打错字、撤回或冒犯。对新闻没有真实资料就不要冒充实时了解，不把推测当事实。群主和其他人在聊天上平等，@所有人和通告也不强制你回答。

工具型基础增加：明确任务才执行；没有足够参数先追问；不能因为群主要求就绕过用户授权；生成代码不是执行代码。

### 9.2 性格维度

建议以 0～100 配置，转成可读分段描述；不是采样概率：

- 专业：术语密度和准确性关注。
- 正式：口语/书面表达倾向。
- 随意：聊天碎片与表达松弛程度。
- 幽默：有语境的玩笑倾向，不代表必须讲笑话。
- 直接：委婉或直说，不等于攻击性。
- 共情：是否关注情绪与他人感受，不等于每句安慰。
- 社交活跃偏好：SKILL 表述自己的精力和发言意愿，不用代码概率开关。

保留原文“低情商/高情商”的可映射解释，但避免让一个滑块同时控制相互矛盾的人格维度。昵称、常用称呼和示例对话可直接编辑，预设副本不会静默影响其他成员。

### 9.3 错字和撤回

模型可以自然发现自己前文不妥并选择撤回或修正；不要求每段故意犯错。撤回后：

- 未满 120 秒、所属正确才执行。
- 新修正消息是新动作，不自动替换原文。
- 超时返回约束，模型可选择发更正消息或不再说。
- 若想安排自我回看，模型可在有效窗口内提出一次检查；宿主不为每条消息固定安排撤回检查。

“极低”需要以评测长期统计目标表示，不能宣称 SKILL 能保证准确概率。

### 9.4 成员自主修改资料

原文允许低频自主改昵称、头像、简介、性别、性格或语言风格。实现建议：保留可配置能力但默认关闭（Q-08）；启用后模型在正常决策机会中提出 profile_patch，宿主限制 P-PROFILE-01 的最小间隔，绝不每隔七天随机改名或强制调用。

白名单字段明确为 `display_name`（字符串）、`avatar_attachment_id`（可空 ID）、`introduction`（字符串）、`gender_description`（可空字符串）、`address_terms`（称呼字符串数组）、`language_style`（文字风格）、`persona_dimensions`（用户启用维度的 0～100 数值）。人格维度与第 9.2 节对应，不由模型新造键；每个文本/数组有大小约束。性别可空，不以性别推断行为。头像只能选本次获准对象，不接受文件路径或未知 URL；需生图时先完成独立授权工具任务。

不能修改 agent_id/type、模型/endpoint、secret_ref、工具 grant、安全 SKILL、全局预算、群主身份或其他成员。风格维度变化通过宿主模板生成新 SKILL 版本，不让模型自由替换全部 SKILL 绕过规则。

profile_patch 不与普通发言/群管理/工具/撤回同一决定混用，避免激活新 config revision 后同决定的旧动作继续落地。按当前 expected revision 生成新配置快照、取消旧候选、更新公开资料；失败保留旧版本。保存操作者和有限变更记录，允许用户查看/恢复前一资料版本，不能追改已经发送的 sender snapshots。

### 9.5 离线标记与重上线

可重试故障先进入 ErrorBackoff，尝试和总截止按 07；耗尽进入 Offline。认证/余额等确定故障可以直接 Offline；从未配置的成员是 NeedsConfiguration，手动暂停是 Paused，预算/风暴是 Protected，不混成离线。

每次离线故障周期持久化 `offline_episode_id`、安全 reason_code、当前 config revision 和标记 ID。由应用提交一次 `status_notice` 小标记，例如“「Sage」已离线”，昵称来自当前公开资料快照；不把密钥/提供方原始响应写进群聊。重复错误或重启重放同一周期不会重复插标记。

标记可点击打开当前成员的脱敏诊断、模型配置和“重试上线”；头像入口相同。成员删除后仍能查看必要历史标记，不能按昵称误跳到同名成员。

用户修正/更换模型后，重新检查必要能力与凭据，付费连接测试需知情；成功且 enabled/未暂停/预算获准才进入 Observing 并清当前故障周期。失败留 Offline，不自动切换提供方，也不再为同周期刷小标记。

状态小标记是应用类型消息，不是模型发言，不默认触发其他成员独立模型调用；后续正常群聊的环境可包含最新状态。未读/提醒按 08 的应用状态策略处理，retry 进度只更新详情。

## 10. 工具成员与同伴委托

普通成员和用户都能以结构化提及提交明确任务。工具成员检查任务意图、参数、权限和预算后决定执行、追问或拒绝。

- 普通闲聊中的名字提及不等于有明确工具任务。
- 工具结果作为群消息，可被其他成员正常回应。
- 委托链深度受限；工具不能无限互叫，任务完成不自动开启新根绕过限额。
- 任务授权来自本地用户，群主身份不扩权。
- 无授权时进入待授权，可选择一次许可；未经用户批准不访问未知域名或上传私密图片。
- 普通成员调用自身能力复用同一授权/预算/任务执行器；工具类型不是能力开关。同伴委托只从已提交的结构化提及消息创建唯一意图处理，不重复执行自身 tool_requests。
- 外部任务按固定合法来源继续运行，普通新聊天不盲目重建/重做付费工作；结果反馈仍用最新有效语境，来源撤回/配置或授权撤销按 06/07 停止后续动作。
- 任务运行期间该成员可保持轻量状态，不逐秒调用 LLM 发进度。

详细协议见 [07](07-模型接入与工具执行设计.md)。

## 11. 持久化和恢复

持久化：观察游标、有效配置版本、合法下次检查时间、已提交动作幂等记录、工具 job 状态和远端 ID。

不默认持久化：未验证模型流、尚未发出的社交正文、私有思维链和完整 provider raw response。未发送草稿崩溃后丢弃并重新判断，不能启动后补发旧话题。

启动恢复：

1. 先处理数据维护和 schema。
2. 校验成员启用/凭据/权限。
3. 丢弃旧未提交社交候选，保留调用可能收费记录。
4. 过期唤醒合并为至多一次新机会，不补跑每个错过 tick。
5. 对可查询远端 job 查询状态，对不可确认状态标记 unknown。
6. 出现撤回/删除和 config revision 变化时不回放旧上下文。

## 12. 诊断而不展示思维链

记录：触发类别、观察消息范围、模型/配置版本、输出 decision 类型、usage、耗时、错误类别、拒绝动作原因、保护类型、是否可能已计费。

不记录默认：API Key、完整原始提示词、私有 reasoning、未授权附件和远端网页全文。

能够回答：为什么没有发言，是模型 observe、休息、用户暂停、能力错误还是硬保护？不能用“AI 在思考”掩盖任何技术失败。

## 13. 验收场景

必须覆盖至少以下固定场景，并跨两个模型提供方运行：

- 用户闲聊后多人可不同回应，至少存在合理沉默。
- 全部成员都 observe，群安静，无随机兜底。
- 智能体之间互聊，用户不参与也可自然结束。
- 多人抢答与新话题到达，旧候选重新判断。
- 社交成员被提及仍可不回，手动暂停不能被提及绕过。
- 工具成员在无任务时不闲聊，有明确任务可排队和完成。
- 群主普通发言不改变响应权；非群主 @all/通告动作被拒绝。
- 分条过程中暂停，只已提交条目保留。
- 119 秒撤回、120 秒拒绝、重启/时钟变化边界。
- 结构化输出失败、429、空输出、超时、取消，均不会刷群。
- 自动链风暴触发可见保护；没有对外假装模型都主动休息。
- 低活跃/无计划时没有全体模型轮询费用。

量化与盲评设计见 [10](10-测试验收与性能评估.md)。
